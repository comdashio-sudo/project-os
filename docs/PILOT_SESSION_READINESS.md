# تجهيز جلسة قبول Pilot

**الحالة:** بروتوكول الجلسة وحزمة التنفيذ جاهزان؛ القبول البشري والهوية الحقيقية ما زالا خارج التنفيذ الآلي.
**المرجع الحاكم:** [STATE.md](./STATE.md) و[حزمة التنفيذ الخارجي](./PILOT_EXTERNAL_EXECUTION_KIT_2026-08-26.md).

> لا ينشئ هذا المستند حسابات بريدية أو كلمات مرور أو رموز OAuth، ولا يقبل حسابات محاكاة كبديل لمستخدمين حقيقيين.

## ما ثبت آليًا

| الدليل | الأمر القابل لإعادة التشغيل | آخر نتيجة مثبتة |
|---|---|---|
| بوابة الوحدة والواجهة | `pnpm test` | 359 اختبارًا ناجحًا و79 اختبارًا حيًا متخطى داخل الأمر العام. |
| فحص الأنواع والبناء | `pnpm check && pnpm build` | ناجحان. |
| جرد إجراءات الأعمال | `pnpm coverage:trpc` | 185 إجراءً و180 مرجعًا مباشرًا و5 استثناءات إطار مسماة وصفر غير مصنف. |
| حراسة التدقيق | `pnpm verify:audit-grants` | `approved: true` مع رفض UPDATE وDELETE لحساب التطبيق. |
| قبول الأدوار والعزل والنسخ المنطقي | `node scripts/run-integration-database-test.mjs` | 79/79 حالة TiDB ناجحة خلال 227.35 ثانية. |

## تسلسل الجلسة بعد رفع الحجب

ينفذ المالك أولًا قبول الدعوة المعلقة، ثم يحدد هويات EXECUTIVE وPMO وPROJECT والحساب منخفض الصلاحية ويعينها عبر إدارة المؤسسة. ينفذ جدول `ROLE-EX-01` إلى `ROLE-LO-01` وجدول `A11Y-01` إلى `A11Y-05` من ملفات القبول. لكل سيناريو يسجل منفذ الجلسة معرفًا مقنعًا ووقت UTC ومرجع تدقيق أو رفض؛ لا يسجل كلمة مرور أو رمزًا أو بيانات عميل.

## حدود الجاهزية

لا يثبت نجاح الاختبارات الآلية جلسة OAuth بشرية أو قارئ شاشة أو ملكية بريد أو بيانات Pilot. لا يوجد claim موثق لـ`email_verified` ولا مزود بريد معتمد حاليًا، والنشر العام عند نقطة التحقق ما زال `BLOCKED_BY_PLATFORM`. لذلك لا يحول هذا المستند أي قيد `HANDOFF_REQUIRED` أو `BLOCKED_BY_OWNER` إلى GO.
