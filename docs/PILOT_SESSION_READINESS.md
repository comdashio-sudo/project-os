# تجهيز جلسة قبول Pilot

**الحالة:** البروتوكول والأدلة الآلية جاهزة؛ إنشاء مستأجر Pilot الحقيقي وتعيين أربع هويات OAuth حقيقية **محجوب بالمالك**.

> لا يقبل هذا المستند حسابات تجريبية مصطنعة أو كلمات مرور أو رموز OAuth. دليل التكامل المنعزل يثبت الحراس، لكنه لا ينشئ جلسات بشرية حقيقية.

## ما ثُبّت آليًا

| الدليل | الأمر القابل لإعادة التشغيل | النتيجة المثبتة في 21 أغسطس 2026 |
|---|---|---|
| بوابة الوحدة والواجهة | `pnpm test` | 274 اختبارًا ناجحًا و61 اختبارًا تكامليًا متخطى داخل أمر الوحدة لأن له مشغلًا مستقلًا. |
| فحص الأنواع والبناء | `pnpm check && pnpm build` | مكتملان؛ يبقى تحذير حجم حزمة Vite غير حاجب للبناء. |
| جرد إجراءات الأعمال | `pnpm coverage:trpc` | 117 إجراءً و112 مرجع تكامل مباشر و5 استثناءات إطار مسماة وصفر غير مصنف. |
| حراسة التدقيق | `pnpm verify:audit-grants` | `approved: true` مع رفض UPDATE وDELETE. |
| قبول الأدوار والعزل | `node scripts/run-integration-database-test.mjs` | 61/61 حالة؛ تشمل قبول أدوار منظمًا ونسخ/استرجاع Pilot منطقيًا في قاعدة الاختبار المعزولة. |

## عناصر التحضير

| المعرف | العنصر | الحالة | المالك المطلوب | سبب الحالة |
|---|---|---|---|---|
| `PRE-01` | تعيين أربع هويات مستقلة: EXECUTIVE وPMO وPROJECT ومنخفض الصلاحية | `BLOCKED_BY_OWNER` | مالك Pilot أو مسؤول الهوية | التطبيق يعتمد OAuth؛ لا توجد هويات بشرية يمكن اختراعها من المستودع أو من قاعدة الاختبار. |
| `PRE-02` | اسم مستأجر Pilot ومالك بيانات ومشروع اختبار قابل للحذف | `BLOCKED_BY_OWNER` | مالك Pilot | يمنع إنشاء بيانات تعمل كأنها بيانات عميل أو اختيار مالك بيانات بالافتراض. |
| `PRE-03` | أربعة تعيينات دور ونطاق داخل المستأجر المحدد | `READY_AFTER_PRE-01_PRE-02` | مسؤول المستأجر | مسارات العضوية والأدوار موجودة ومثبتة؛ لا تنفذ قبل توفر الهويات والمستأجر. |
| `PRE-04` | سطح المكتب والجوال وقارئ الشاشة | `HANDOFF_REQUIRED` | منفذ الجلسة البشرية | يلزم جهاز وصوت مستخدم حقيقي؛ لا يعوضه اختبار DOM. |
| `PRE-05` | نسخة منشورة يحددها المالك | `BLOCKED_BY_PLATFORM` | مالك النشر | نقطة التحقق تصل النطاق العام تلقائيًا، لذا لا تنشأ بلا موافقة صريحة. |

## تسلسل الجلسة بعد رفع الحجب

يُنشأ المستأجر من واجهة الإدارة تحت مالك البيانات المعتمد، ثم تُقبل الهويات الأربع في OAuth وتُسند عضويات منفصلة ونطاقات مناسبة. بعد ذلك ينفذ جدول `ROLE-EX-01` إلى `ROLE-LO-01` وجدول `A11Y-01` إلى `A11Y-05` كما هما في [MANUAL_ACCESSIBILITY_ACCEPTANCE.md](./MANUAL_ACCESSIBILITY_ACCEPTANCE.md). يسجل معرّف مستخدم مقنّع ووقت UTC ومرجع التدقيق، ولا تسجل أي كلمة مرور أو رمز أو بيانات عميل.

## حدود الجاهزية

البيئة الآلية الحالية تثبت الرفض قبل الكتابة، والأثر التشغيلي والسجل التدقيقي ضمن قاعدة الاختبار المعزولة. لكنها لا تثبت جلسة OAuth بشرية أو قارئ شاشة أو ملكية بيانات Pilot. لذلك لا يمنح هذا المستند حكم `GO` ولا يحول `HANDOFF_REQUIRED` أو `BLOCKED_BY_OWNER` إلى دليل منفذ.
