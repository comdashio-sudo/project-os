# خطة توسيع اختبار التكامل التشغيلي

تغطي قاعدة `project_os_integration_test` حاليًا HSE وNCR وRFI والقضايا والعقود والموارد والمطالبات والمستندات وطلبات التغيير والإشعارات والتدفق النقدي التنفيذي. تثبت الحالات الرفض العابر والسماح والتدقيق في السجلات التي يغطيها المشغل.

| الأولوية التالية | حالة الدليل الحالي | الإجراء المطلوب |
|---|---|---|
| الالتزامات | دليل tRPC فعلي متحقق. | رُفض مشروع مستأجر آخر، وأُنشئ التزام مشروع مصرح به بسجل تدقيق واحد ثم نُظفت بياناته داخل الحالة. |
| قرارات القيادة | اختبار واجهة وتفويض. | إضافة إنشاء وقراءة مقيدين في قاعدة التكامل. |
| المحافظ والبرامج | اختبارات تفويض وواجهة. | إضافة إنشاء وربط عابر/صحيح في قاعدة التكامل. |
| المخاطر والإجراءات | اختبارات تفويض. | إضافة رفض وسماح وتدقيق في قاعدة التكامل. |
| المستشار الذكي | اختبار DOM وفحص نموذج حي. | يبقى اختباره طرفيًا مستقلًا لتجنب تكلفة نموذج في كل مسار انحدار؛ تثبت صلاحية المشروع قبل الاستدعاء عبر قراءة Level 3 المحكومة. |

لا تغلق هذه الخطة فجوة مشغلات `audit_logs` في TiDB Serverless؛ تظل تلك فجوة بيئية موثقة تتطلب MySQL/InnoDB أو حساب تشغيل محدود لإغلاقها على مستوى قاعدة البيانات.
