# نواة Master Plan

## النطاق المنفذ

تضيف النواة Master Plan مرقّمًا لكل مشروع، بسجل إصدارات لا يستبدل التاريخ وكيانات مكانية قابلة للعرض والتصفية. يدعم الإصدار `original` عند الإنشاء ثم `revision` و`updated` لاحقًا، ويحفظ رقم الإصدار والوصف وملخص التغيير وفاعل الرفع. تبقى بيانات الملف الاختيارية في التخزين الكائني عند تقديمها؛ لا تُحفظ بايتات الملف داخل قاعدة البيانات.

| الكيان | العزل والفرض | بيانات جوهرية |
|---|---|---|
| `master_plans` | المستأجر + المشروع + `PROJECT/project.write` للإنشاء | رمز، عنوان، حالة، منشئ |
| `master_plan_versions` | يتبع الخطة والمشروع نفسيهما | رقم، نوع، وصف، ملخص تغيير، بيانات ملف اختيارية، رافع |
| `master_plan_spatial_entities` | يتبع إصدارًا ومشروعًا محددين | كود، نوع، هندسة 100×100، حالة، تقدم، PV/Actual/Forecast، روابط WBS/نشاط اختيارية |

تتحقق خدمة الكيان المكاني من أن حدوده المربعة تقع داخل مخطط 100×100، وأن نسب التقدم بين 0 و100، وأن الأب وWBS والنشاط—عند وجودهم—تابعون للمشروع والإصدار ذاتهما. تكتب عمليات الإنشاء والتعديل سجلات تدقيق خادمية ضمن المعاملة.

## التجربة المرئية

تظهر في Level 3 بطاقة Master Plan ثنائية اللغة، تختار الخطة والإصدار، وتبحث في الكيانات وتصفّيها بالحالة. يُرسم كل كيان بمستطيل نسبي ضمن سطح 100×100، ويعرض الضغط عليه بيانات النوع والحالة والتقدم والقيم المخططة والفعلية والمتوقعة. لا يُحمّل الرسم أي كيان من خارج الاستعلام المشروع-المحكوم.

## ربط Excel الأولي

تقبل واجهة Master Plan ملف `XLSX` أو `CSV` لإصدار محدد وتربط الصفوف بالكيانات المكانية الموجودة بواسطة رمز الوحدة فقط. يتعرف المحلل على عناوين عربية وإنجليزية لـ **Unit ID / رقم الوحدة**، والحالة والتقدم والقيم المخططة والفعلية والمتوقعة، ويقبل قيمة Excel النسبية `0.84` على أنها `84%`. لا ينشئ الربط كيانات جديدة ولا يغيّر هندستها أو روابط WBS والأنشطة؛ الهدف هو تحديث KPI للكيانات التي سبق تعريفها.

يعيد الخادم تحليل الملف داخل الطلب، ويفرض `PROJECT/project.write` وميزة `MASTER_PLAN` وملكية المشروع والإصدار قبل التحديث. يرفض الصفوف غير الصالحة والرموز المكررة والرمز غير المطابق لكيان الإصدار قبل فتح معاملة التحديث. ثم يحدث الصفوف المصرح بها فقط ويكتب حدث `master_plans.excel_mapping_applied` واحدًا يحوي بصمة الملف وعدد الصفوف.

## أدلة التحقق

| الدليل | النتيجة |
|---|---|
| ترحيل `0015_colorful_ultimatum.sql` | أُنشئت الجداول الثلاثة وقيودها وفهارسها. قُصرت أسماء القيود لتوافق حد معرف MySQL/TiDB بعد فشل أولي بلا فقد بيانات، ثم تحققت الجداول والفهارس حيًا. |
| تكامل MySQL/TiDB | رُفضت محاولة إنشاء Master Plan لمشروع مستأجر آخر، ثم أُنشئت خطة وإصدار مراجعة وكيان مكاني وسجلات التدقيق الثلاثة للمشروع المصرح. |
| اختبار تفاعل DOM | اختير الكيان المكاني `ZONE-A` وظهرت تفاصيل التقدم والقيم المخططة والفعلية والمتوقعة. |
| اختبار محلل الربط | ثبت تعيين رؤوس عربية وCSV ذي BOM وتحويل النسبة النسبية ورفض الحالة غير الصالحة. |
| اختبار التفاعل | رفع المستخدم CSV للإصدار المختار وأرسل العميل المستأجر والمشروع والإصدار والصيغة والمحتوى إلى العقد المحمي. |
| تكامل الربط | رُفض سياق مشروع عابر، ثم حدّث CSV الكيان `ZONE-A` إلى 84% وحالة مكتمل وقيمة فعلية 90 مع سجل تدقيق إضافي. |
| بوابة الجودة | اجتاز `pnpm test && pnpm check && pnpm build && node scripts/run-integration-database-test.mjs`؛ يشمل ذلك 29 حالة تكامل فعلية. |

## حدود معلنة

هذه نواة خفيفة تعتمد سطح HTML نسبيًا للآلاف الأولى من الكيانات المرئية بعد التصفية. لم يُنفذ بعد محرر هندسة احترافي أو Canvas/WebGL لعشرات الآلاف، أو إنشاء كيانات وإحداثيات من Excel، أو حفظ لقطات العرض، أو الربط العكسي إلى صفحات WBS/الأنشطة/المستندات، أو تنبيهات الإنتاج والجودة وHSE. لا تدعي هذه الدفعة إغلاق تلك المتطلبات.
