# روابط سجلات الحوكمة

## النطاق

يوفر سجل روابط الحوكمة علاقة قابلة للتدقيق بين **المخاطر** و**القضايا** و**الإجراءات** و**القرارات** داخل مشروع واحد. يمثّل الرابط مصدرًا وهدفًا موجّهين، لذلك يمكن ربط مخاطرة بإجراء تخفيف أو قضية بقرار من دون تخزين معرّف خام غير محكوم في أي سجل من السجلات الأصلية.

## الحراسة الخادمية

| القيد | الفرض المطبق |
|---|---|
| حزمة وصلاحية PMO | تتطلب القراءة والإنشاء حزمة PMO وصلاحية `pmo.write` ونطاق المشروع. |
| ملكية المصدر والهدف | يعيد الخادم اختيار كل سجل وفق نوعه ومعرّفه والمستأجر والمشروع قبل إدراج الرابط. |
| الأنواع | يقتصر المصدر والهدف على `risk` و`issue` و`action` و`decision`. |
| منع الحالة الخاطئة | يرفض الرابط الذاتي والرابط المكرر، ويفرض الفهرس الفريد العلاقة نفسها على مستوى قاعدة البيانات. |
| أثر التدقيق | يكتب إنشاء كل رابط وسجل تدقيق `governance.control_record_link_created` داخل المعاملة نفسها. |

## الواجهة

تظهر بطاقة **روابط سجلات الحوكمة** في لوحة Level 2. يختار المستخدم مشروعًا ثم مصدرًا وهدفًا من السجلات المفتوحة المصرح بها لذلك المشروع؛ لا تقبل الواجهة إدخال معرّفات يدويًا. تقرأ اللوحة القرارات ضمن عقد PMO المحكوم لتصبح قابلة للاختيار، وتحصر السجلات القابلة للربط في المخاطر والقضايا والإجراءات المفتوحة والقرارات غير المنفذة أو المرفوضة.

## التحقق المثبت

يثبت تكامل MySQL/TiDB رفض مصدر أجنبي، والرابط الذاتي، والرابط المكرر، ثم إنشاء رابط مخاطرة إلى إجراء ورابط قضية إلى قرار داخل المشروع المصرح به، مع سجلين تدقيقيين. تثبت اختبارات DOM تمرير النوع والمعرّف والنطاق الصحيحين للرابط، والعناوين والأزرار العربية والإنجليزية. اجتازت البوابة الكاملة 220 اختبارًا قياسيًا و38 اختبار تكامل فعليًا.

## الحد الحالي

لا يربط هذا الإصدار بعد المستندات أو WBS أو RFI أو NCR أو أوامر الشراء بسجل الروابط. تمتثل هذه الروابط للأنواع الأربعة المحددة وتحتاج أي توسعة مستقبلية إلى تحقق ملكية مكافئ لكل نوع جديد.
