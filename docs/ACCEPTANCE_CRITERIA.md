# معايير قبول PROJECT OS

## قاعدة الحكم

تعد ميزة ما مقبولة عندما يثبت دليل قابل لإعادة التشغيل أن مسارها المصرح يعمل، وأن مسار المستأجر أو المشروع أو الحزمة غير المصرح به يرفض قبل إرجاع بيانات أو كتابة سجل أعمال، وأن النص الظاهر متاح بالعربية والإنجليزية. البناء وحده لا يحقق القبول.

| الدليل | الحد الأدنى المطلوب |
|---|---|
| السلوك | اختبار وحدة أو tRPC أو واجهة يغطي الناتج المتوقع. |
| العزل | حالة رفض مستأجر/مشروع/مستلم عابر عند وجود نطاق. |
| التدقيق | تحقق من سجل تدقيق عند كل عملية كتابة تشغيليّة. |
| التعريب | نص عربي وإنجليزي واضح أو خريطة رمز آمنة بدل نص خطأ خام. |
| الانحدار | `pnpm test && pnpm check && pnpm build` ناجح. |

## قبول النواة المشتركة

| المجال | معيار القبول | الدليل الحالي | الحالة |
|---|---|---|---|
| الهوية والعضوية | العضوية الفعالة، الأدوار، النطاقات، والدعوات لا تمنح امتيازًا ذاتيًا، ولا يمكن للعضو تعطيل أو إعادة تفعيل عضويته. | اختبارات تفويض RBAC ومسارات الدعوة وتعيين/إلغاء الدور، وتكامل حي يثبت منع التعديل الذاتي والعزل والانتقال القانوني والتدقيق. | منفذ لنطاق المسارات المثبتة؛ تبقى الحدود العامة معلنة. |
| الاستحقاقات | يمنع كل مسار مستوى لا تتضمنه الحزمة. | `assertTenantAccess` واختبارات PROJECT وPMO وEXECUTIVE. | منفذ جزئيًا؛ يلزم اتساع تغطية جميع الإجراءات. |
| العزل | لا يعاد أو ينشأ سجل عابر للمستأجر أو المشروع. | اختبارات تشغيلية وتكاملية HSE/NCR/RFI/عقد/التزام/قرار/محفظة/برنامج/مخاطر/إجراء/تغيير/موارد/مطالبة وتدفق تنفيذي. | منفذ للنطاقات المثبتة؛ ما زال التوسع الشامل مفتوحًا. |
| التدقيق | تنشأ عمليات الكتابة وسجل التدقيق معًا من الخادم، ويستخدم التطبيق قبل الـPilot حسابًا لا يملك على `audit_logs` إلا `SELECT` و`INSERT`. | معاملات خادمية واختبارات تحقق من سجل تدقيق، و`ADR-0001-AUDIT-LOG-ACCESS-CONTROL.md` مع `SHOW GRANTS` واختبار رفض تشغيليين مطلوبين قبل الـPilot. | منفذ برمجيًا؛ قبول الـPilot معلق على تنفيذ مسؤول قاعدة البيانات والإفصاح المعتمد. |
| اللغات | زر اللغة يضبط RTL/LTR وتتوفر الأخطاء والسجلات بالعربية والإنجليزية. | `LanguageContext` واختبارات DOM. | منفذ للنطاقات المغطاة. |
| الاستجابة والوضوح المرئي | تعرض جميع المسارات المصرح بها في الموجّه تخطيطًا صالحًا للمس على الجوال وتسلسلًا واضحًا على سطح المكتب، دون قص هوية التطبيق أو عناصر الإجراء الأساسية. | تدقيق مرئي موثق في `UI_RESPONSIVE_AUDIT.md` لمسارات الصفحة الرئيسية وEVM وLevel 1–3 والتراخيص وإدارة المؤسسة وسجل المشاريع، بمقاسي `1280×720` و`375×812`، مع إصلاح التفاف علامة PROJECT OS وأدلة منع مباشرة للحساب المقيد، وتسميات وترتيب تركيز آليين لسجل المشاريع والملاحة المؤسسية. | منفذ لنطاق المسارات الحالي؛ تبقى مراجعة قارئات الشاشة والتنقل اليدوي الشامل وحدًا معلنًا خارج هذا التدقيق. |

## Level 1 — القيادة التنفيذية

يقبل مستوى القيادة عندما يمنح حامل EXECUTIVE وصلاحية `executive.read` رؤية المشاريع والقرارات ضمن المستأجر فقط، ويمنع غير المرخص قبل تحميل البيانات. يجب أن تعرض لوحة القيادة الميزانية والتكلفة والتوقعات والقرارات المفتوحة، وملخص التدفق النقدي الذي يحسب الميزانية المخططة والتكلفة الفعلية والالتزامات والتعرض والمتبقي من مصادر مقيدة بالمستأجر.

| معيار خاص | دليل القبول الحالي |
|---|---|
| القرارات التنفيذية | إنشاء قرار مرتبط بالمشروع ضمن الصلاحية والتدقيق الذري، مع دليل tRPC فعلي للرفض العابر والسماح. |
| مؤشرات المحفظة | قراءة مقيدة بـ`tenantId` مع حالة فراغ موطنة. |
| التدفق النقدي | اختبار tRPC فعلي يستبعد مصدر مستأجر آخر وقيد تكلفة ملغى والتزامًا ملغى، مع نتيجة ثابتة قابلة للتحقق. |
| العرض | اختبار DOM للملخص بالعربية والإنجليزية وتفصيل حسب المشروع، ورسم محافظ محمل عند الحاجة. |

## Level 2 — PMO

يقبل مستوى PMO عندما يمنح حامل PMO وصلاحيتي القراءة أو الكتابة وفق العملية، ويستطيع إدارة المحافظ والبرامج وربط المشروع وإدارة المخاطر والقضايا والإجراءات والتصعيدات دون تجاوز نطاق المستأجر أو المشروع.

| معيار خاص | دليل القبول الحالي |
|---|---|
| بيانات المحافظ والبرامج | دليل tRPC فعلي يرفض محفظة عابرة وينشئ محفظة وبرنامجًا ويربط المشروع الصحيح مع تدقيق. |
| المخاطر والقضايا والإجراءات | كتابة محكومة بحزمة PMO وتدقيق ذري؛ يثبت تكامل فعلي رفض خطر وإجراء عابرين والسماح بالسجلين الصحيحين. |
| التصعيدات | خريطة خادمية `none → pending → escalated` تمنع القفز وتعيد التحقق من الحرجة أو التأخر. |
| العرض | لوحة ثنائية اللغة تعرض سجلات PMO والحالات وخطوات الانتقال المتاحة فقط. |
| متابعة التخطيط متعددة المشاريع | تجميع خادمي لآخر SPI/CPI وEAC/VAC وصحة المشروع وتوقع النهاية والاستثناءات، مع فرز الاستثناءات أولًا ومرشح جميع المشاريع أو البيانات الناقصة. |

## Level 3 — تسليم المشروع

يقبل مستوى التسليم عندما يفرض `project.read` للقراءة و`project.write` للكتابة ضمن نطاق المشروع، وتعمل السجلات التشغيلية دون الاعتماد على حماية الواجهة.

| المجال | معيار القبول الحالي |
|---|---|
| التخطيط وEVM | WBS والميزانيات والتكلفة والتقدم والأنشطة تجمع إلى PV وEV وAC وBAC، وتغطي الخدمة معادلات CPI/SPI/EAC/ETC/VAC. |
| العقود والتدفق المالي | عقود والتزامات وتدفق نقدي يحسب التعرض والمتبقي ويستبعد الحالات الملغاة. |
| الموارد والقدرة | سجل موارد مع حد `allocatedUnits ≤ plannedUnits` مفروض قبل الكتابة، ونسبة تخصيص ذات مقام معلن. |
| المطالبات | سجل مطالبات مع دورة `draft → submitted → under_review → approved/rejected/withdrawn` وحد قيمة اعتماد صريح وتدقيق. |
| المستشار الذكي | قراءة خادمية منظمة من لقطة المشروع، موسومة Actual/Calculated/Forecast/Assumption/Recommendation ولا تعدل البيانات. |
| المستندات | رفع خادمي إلى تخزين كائني مع بصمة ومفتاح مولدين خادميًا ودورة مراجعة محكومة. |
| RFI/NCR/HSE/التغييرات | سجلات معزولة ودورات حالة خادمية وتدقيق وعرض ثنائي اللغة. |
| الاستيراد والتصدير | تحليل وتأكيد استيراد WBS والميزانية بسياسات تكرار محفوظة ونتائج صفوف؛ يفرض ملفًا وورقةً ونوع بيانات واحدًا ويرفض عمودًا غير معتمد أو مفتاحًا مكررًا داخل الملف. يصدّر WBS والميزانية والأنشطة بصيغتي XLSX وCSV بعد فحص الاستحقاق والنطاق. يثبت التكامل رفض تصدير مشروع عابر ثم CSV مصرحًا وسجل `data_export_generated` واحدًا. |
| التقارير والجودة | التقارير الميدانية وفحوصات الجودة محكومة بالمستأجر والمشروع، بدورات حالة محددة وتدقيق ذري؛ ينشئ اعتماد أو رفض التقرير إشعارًا داخليًا لصاحبه فقط. |
| أوامر الشراء والروابط | أمر الشراء يربط اختياريًا بعقد أو التزام من المشروع نفسه ويسجل الاستلام خادميًا؛ وروابط الحوكمة تقيد المصدر بسجلات PMO والهدف بسجلات الحوكمة أو RFI أو NCR ضمن النطاق. |
| صحة المشروع والإشعارات | لقطة صحة من مصادر تشغيلية موثقة وإشعارات داخلية للمستلم فقط. |

## حدود القبول المفتوحة

| الحد | أثره | مسار الإغلاق |
|---|---|---|
| TiDB Serverless لا يدعم triggers | لا يمكن منع تعديل أو حذف `audit_logs` عبر قاعدة البيانات في البيئة الحالية. | ينفذ مسؤول قاعدة البيانات قبل الـPilot الحساب التشغيلي المقيد وحساب القراءة والحساب الإداري المنفصل وفق `ADR-0001-AUDIT-LOG-ACCESS-CONTROL.md`، ثم يحتفظ بـ`SHOW GRANTS` واختبار الرفض والإفصاح القانوني. |
| دقة عمق تكامل الإجراءات | يغطي الجرد كل إجراء أعمال بمرجع تكاملي مباشر، لكن المرجع ليس بديلًا عن اختبار يدوي لكل دور ومسار مستخدم وإدارة تشغيل حية. | الحفاظ على ربط كل إجراء جديد بحالة رفض وسماح وتنظيف، وإجراء اختبارات قبول يدوية للأدوار والمسارات عند جاهزية بيانات التشغيل. |
| الإشعار الخارجي | الإشعارات الحالية داخلية فقط ولا ترسل بريدًا أو رسالة خارجية. | اعتماد قناة خارجية وسياسة تسليم ثم اختبارها. |

تجمع `TEST_EVIDENCE_MATRIX.md` أوامر إعادة التشغيل ونتائج **245 اختبار وحدة وواجهة** و**58 حالة تكامل tRPC حية**، وتفصل بين المجال المثبت وحدود عدم التعداد الحرفي لكل إجراء مستقبلي أو اختبار وصول شامل. تثبت اختبارات DOM المنع الموطّن أو إخفاء الضوابط في الشاشات الحرجة، وتسلسل التركيز والتسميات في سجل المشاريع والملاحة المؤسسية؛ ولا يساوي ذلك مراجعة قارئ شاشة شاملة.

يتحقق `pnpm coverage:trpc` من أن كل إجراء أعمال في الموجّه له مرجع تكاملي مباشر، أو أنه استثناء إطار موثق بالاسم. سجّل آخر تشغيل **97 مرجعًا مباشرًا من 102 إجراء**، مع خمسة استثناءات إطار وصفر إجراء غير مصنف.

## بوابة القبول النهائية

لا يصدر وصف "Production-Ready" إلا عند إغلاق الحدود الوظيفية والأمنية المتبقية، وتنفيذ اختبارات التكامل المرخصة الشاملة، وتوثيق نتائج بيئة الإنتاج الفعلية. قبل ذلك، تشير نقاط التحقق إلى دفعات متحققة محددة لا إلى قبول نهائي كامل.
