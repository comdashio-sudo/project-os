# معمارية PROJECT OS

## مبدأ التصميم

PROJECT OS منصة مؤسسية معيارية تعمل عبر نواة مشتركة وحدود منتجات صارمة. تعمل المنتجات **EXECUTIVE** و**PMO** و**PROJECT** منفردة أو متصلة، بينما يفرض الخادم وقاعدة البيانات الاستحقاقات والصلاحيات، ولا يقتصر ذلك على إخفاء عناصر الواجهة.

## الطبقات

| الطبقة | المسؤولية | قواعد العزل |
|---|---|---|
| واجهة React وTypeScript | عرض لوحات Level 1 وLevel 2 وLevel 3، إدخال البيانات، حالات التحميل والخطأ والمنع. | لا تُعد الواجهة مصدرًا للقرار الأمني. |
| واجهة API محمية | تحقق الجلسة، RBAC، الاستحقاق، التحقق من المدخلات، سجل التدقيق. | كل إجراء يطلب سياق مستخدم ومستأجر. |
| خدمات المجال | EVM، صحة المشروع، الاستثناءات، سير العمل، التقارير. | حسابات مركزية قابلة للاختبار بلا اعتماد على الواجهة. |
| MySQL | بيانات معيارية، علاقات، فهارس، قيود، سجلات تدقيق. | كل كيان أعمال يملك `tenantId` ومفاتيح/فهارس نطاقية. |
| التخزين الآمن | بيانات وصفية وإصدارات مستندات فقط في قاعدة البيانات، والملفات في تخزين منفصل. | تفويض الوصول قبل إصدار أي رابط تحميل. |

## حدود المنتجات

| المنتج | المنتج المستقل | البيانات التي يستهلكها في الوضع المتصل |
|---|---|---|
| EXECUTIVE | Level 1: الاستثناءات والمحفظة والقرارات والذكاء التنفيذي. | مؤشرات متحكم بها من PMO والمشروع. |
| PMO | Level 2: الحوكمة والضوابط والمحافظ والبرامج. | بيانات تشغيلية من PROJECT وقرارات/توجيهات من EXECUTIVE عند توفره. |
| PROJECT | Level 3: إعداد المشروع والتنفيذ والضوابط اليومية. | معايير وحوكمة PMO عند توفره فقط. |

## قرار تقني مسجل

تعتمد المنصة في هذه المساحة على React وTypeScript وخدمة Express وقاعدة **MySQL/TiDB Serverless** عبر `drizzle-orm/mysql2` و`mysqlTable` وترحيلات MySQL. لا توجد تبعية تشغيلية لـSupabase أو PostgreSQL في PROJECT OS الحالي، ولا يصح استخدام اتصال PostgreSQL لاختبار هذا المستودع أو نشره دون مشروع تحويل معماري مستقل يشمل طبقة ORM والمخطط والترحيلات والاختبارات. توضع ملفات إعداد Vercel لاحقًا لملاءمة حزمة النشر، لكن لا يتم أي نشر خارجي تلقائيًا.
