# تصميم السلسلة التجارية — BOQ والمشتريات ومقاولو الباطن

## قرار النطاق

يمثل `budget_lines` خط الأساس المالي الحالي فقط، ولا يحمل كمية أو وحدة أو سعر بند أو تعريفًا مستقلًا لبند BOQ؛ لذلك لا يصلح وحده لمنع تجاوز كميات مقاول الباطن أو تتبع شراءٍ لبند. ستضاف بنود BOQ مستقلة داخل المشروع، مرتبطة اختياريًا بـWBS وبـ`budget_lines`، وتكون هي مصدر الكمية والقيمة التعاقدية للتخصيصات التجارية.

لا يستخدم جدول `invoices` الحالي لفواتير مقاول الباطن لأنه مفروض لعلاقة اشتراك المنصة (`subscriptionId`) وترقيمها. ستنشأ فاتورة مشروع/مقاول باطن مستقلة من مستخلص معتمد، ولا تفتح بوابة دفع أو تفرض امتثالًا ضريبيًا غير متوفر.

| الرابط | المصدر الحاكم | القيد |
|---|---|---|
| BOQ ↔ WBS/ميزانية | `boq_items` مع `wbsItemId` و`budgetLineId` اختياريين | التحقق من أن كل المراجع في المستأجر والمشروع نفسيهما. |
| شراء ↔ BOQ | تخصيصات أمر الشراء إلى بنود BOQ | لا يتجاوز مجموع التخصيصات قيمة الأمر ولا قيمة بند BOQ المتاحة. |
| مقاول باطن ↔ عقد | عقد مشروع محدد بنوع `subcontract` ومورد/مقاول مسجل | لا يبدأ مستخلص إلا لعقد نشط ونفس العملة. |
| مستخلص ↔ BOQ | سطور قياس كمية حالية وسعر متعاقد عليه | مجموع الكميات المعتمدة لكل بند لا يتجاوز الكمية التعاقدية. |
| مستخلص معتمد ↔ تكلفة/فاتورة | تكلفة فعلية منشورة وفاتورة مشروع منفصلة في معاملة واحدة | لا تصدر الفاتورة ولا تنشر التكلفة قبل الاعتماد، ولا يعاد إصدارها للمستخلص نفسه. |

## دورة الحالة المحافظة

> `draft → submitted → approved | rejected → invoiced`

لا يسمح بالانتقال إلى `approved` أو `invoiced` إلا مع سطور صالحة وحراسة المشروع. يحجز الاعتماد الكمية المرصودة داخل المعاملة بقفل بنود BOQ وصفوف المستخلصات السابقة، ويحسب صافي المستخلص من إجمالي الأعمال المعتمدة ناقص الاحتجاز المعلن. لا يُستبدل سجل قرار الاعتماد بتحديث قابل للتراجع، بل يسجل التدقيق الذري كل انتقال وأثر تكلفة/فاتورة.

## حدود هذه الدفعة

لا تشمل السلسلة دفعات بنكية أو تسوية ضرائب أو شهادة ZATCA أو توقيعًا إلكترونيًا أو إقرارًا قانونيًا؛ تلك تكاملات خارجية تتطلب قرار مالك ومزودًا مناسبًا. كما لا تنشئ أمر شراء أو مستخلصًا تلقائيًا من بيانات BOQ؛ المستخدم يسجل المصدر والكمية صراحةً ويثبتها النظام مقابل الحدود.
