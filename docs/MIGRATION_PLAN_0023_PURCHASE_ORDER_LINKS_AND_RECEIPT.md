# خطة ترحيل 0023 — روابط أوامر الشراء والاستلام

## الهدف

يوسع الترحيل جدول `purchase_orders` برابط اختياري لعقد ورابط اختياري لالتزام، وبوقت استلام، ويضيف حالة `received` لدورة الأمر. لا يقبل الخادم أي رابط إلا إذا كان العقد أو الالتزام مملوكًا للمستأجر والمشروع نفسيهما.

## الأثر المتوقع

| العملية | الأثر المتوقع |
|---|---|
| الحقول | إضافة `contractId` و`commitmentId` و`receivedAt` القابلة للفراغ بلا فقد بيانات. |
| العلاقات | منع معرف عقد أو التزام غير صالحين على مستوى قاعدة البيانات، مع إعادة تحقق خادمية للنطاق الثلاثي. |
| الحالة | توسيع قيمة الحالة لتشمل `received`، ولا تصل إليها الخدمة إلا من `issued`. |
| الفهرسة | إضافة فهارس لقراءة روابط العقد والالتزام. |

## استعلام التحقق

```sql
SELECT column_name
FROM information_schema.columns
WHERE table_schema = DATABASE()
  AND table_name = 'purchase_orders'
  AND column_name IN ('contractId', 'commitmentId', 'receivedAt');
```

## الاسترجاع

لا ينفذ الترحيل حذفًا تلقائيًا. بعد الاستخدام لا يجوز إسقاط الحقول أو إعادة ضبط الحالة إلا ضمن صيانة معتمدة، لأن ذلك يهدم أثر الاستلام والروابط المالية.

## الحدود

لا ينشئ الاستلام قيد تكلفة أو دفعة أو حركة مخزون تلقائيًا. هذه القيود المالية اللاحقة تتطلب نقطة تقارب وحراسة مستقلة.
