## بوابة الدفعة الإلزامية

لا تبدأ أي دفعة تنفيذية جديدة قبل قراءة `docs/ENGINEERING_REFERENCE.md` وتحديد قيد النطاق أو البيانات الذي ستفرضه. ولا تغلق الدفعة عند نجاح البناء وحده؛ يلزم تسجيل أمر التحقق ونتيجته، ودليل رفض للعزل أو الصلاحية حين يكون المسار محميًا، ودليل سماح للمسار الشرعي، ومراجعة المسارات الشقيقة (الإنشاء والقراءة والتحديث أو الانتقال بحسب الوحدة)، والتحقق من النص العربي والإنجليزي الظاهر للمستخدم. يجب تسجيل أي قيد لا يمكن فرضه، مثل منع تعديل أو حذف `audit_logs` في TiDB Serverless، كفجوة صريحة لا كميزة مكتملة. يوثق `docs/ENGINEERING_COMPLIANCE_AUDIT.md` مصفوفة الدليل والفجوات، وتحدّث نقطة الاستئناف في هذا الملف عند كل نقطة تحقق.

تضيف لوحة Level 3 سجلًا ثنائي اللغة للموارد والقدرة يتضمن نموذج إنشاء، تسميات للعمالة والمعدات والمواد والخدمات، ورسالة خطأ موطّنة لحد التخصيص، وقضيب عرض لنسبة التخصيص ذات المقام المحدد (`allocatedUnits / plannedUnits`). لا تُعرض رسائل خادم خام. أثبتت اختبارات التفويض رفض غياب العضوية قبل تحميل المشروع، ورفض تجاوز التخصيص قبل أي استعلام أو معاملة، والسماح الذري مع سجل تدقيق. ويثبت اختبار DOM مباشر إرسال مورد مقيّد، وعرض مقام النسبة، وبقاء الحقول وخطأ موطّن عند الفشل. وأثبت اختبار tRPC فعلي في قاعدة MySQL/TiDB المعزولة رفض مشروع مستأجر آخر وإنشاء مورد المشروع المصرح مع سجل تدقيق واحد وتنظيف كامل. اجتاز `pnpm test && pnpm check && pnpm build` **167 اختبارًا ناجحًا في 18 ملفًا** مع تخطي 13 تكاملًا عند غياب رابط الاختبار، واجتاز المشغل المنفصل **13 اختبار تكامل فعليًا**.
