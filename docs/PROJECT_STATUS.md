# حالة مشروع PROJECT OS

| الحقل | الحالة الحالية |
|---|---|
| المرحلة الحالية | Phase 2 — سجلات التحكم والحوكمة، بعد تأسيس النواة متعددة المستأجرين ومستويات Level 1–3 |
| الوحدة الحالية | حراسة سجلات حوكمة PMO والقرارات التنفيذية؛ اكتملت اختبارات API التشغيلية للمسارات الأربعة، وتنتقل الدفعة التالية لاختبار تكامل حي بقاعدة مستقلة. |
| أعمال مكتملة | تدقيق مستقل، مستودع GitHub خاص مستقل، توثيق البداية، مخطط الشركات والعضويات والأدوار والصلاحيات والاشتراكات والاستحقاقات وسجل التدقيق، ترحيلات ضوابط المشروع، إنشاء مساحة مستأجر فعلي، حاسبة EVM مركزية، محرك صحة المشروع، إجراءات المشاريع ولقطات EVM المحمية، وحارس WBS موحد لمسارات الميزانية والتكلفة والتقدم. أضيفت شاشة Level 3 محمية، ولوحتا Level 1 وLevel 2 بقراءات مقيّدة بالاستحقاق، وسجل PMO تفاعلي ثنائي اللغة للمخاطر والقضايا والإجراءات. كما أضيفت مسارات إنشاء المخاطر والقضايا والإجراءات والقرارات مع فحص استحقاق ونطاق المشروع وكتابة تدقيقية ذرية. نموذج الإجراء يعرض الإجراءات غير المكتملة وغير الملغاة فقط، مع ترجمة الأولويات، وحقل عدد الإجراءات المفتوحة. كما أُصلحت رسالة حفظ القرار التنفيذي وحالة غياب المشاريع. |
| العمل الجاري | تجهيز اختبار تكامل فعلي بقاعدة بيانات اختبارية مستقلة لإثبات العزل الحقيقي خارج doubles الاختبار. |
| التعريب | طبقة لغة مركزية تضبط `lang` و`dir` وتحفظ الاختيار؛ زر اللغة حاضر في رؤوس الواجهات. تضيف طبقة API رموز أخطاء ورسائل آمنة بالعربية والإنجليزية، وتعرض مساحة العمل وسجل المشاريع وحاسبة EVM الرسالة بحسب اللغة الحالية. |
| الاختبارات الفاشلة | لا توجد؛ نجح 43 اختبارًا ضمن سبعة ملفات، وفحص TypeScript والبناء الإنتاجي في هذه الدفعة. يغطي اختبار العرض الخادمي نموذج وسجل الإجراءات بالعربية والإنجليزية، وإرشاد غياب المشروع ورسالة حفظ القرار. وتغطي 12 حالة API إضافية رفض غياب العضوية، ورفض الحزمة الغائبة قبل فحص المشروع، والسماح المشروط بكتابة السجل وسجل التدقيق الذري للمخاطر والقضايا والإجراءات والقرارات. |
| المشكلات المثبتة | أصلح توافق تجميع `Set`، وبنية JSX لمساحة العمل، وفحص نطاق WBS العابر للمشروع، وإظهار رسائل الخادم الخام في واجهات التشغيل. |
| العمل المعلق | اختبار تكامل حقيقي لقاعدة البيانات مستقلة عن المحاكاة، اختبارات السماح التشغيلية، تجميع PV/EV/AC الفعلي من السجلات، الجدولة والأنشطة، واجهات الإجراءات والقرارات، والمستندات وسير العمل. |
| ترحيلات قاعدة البيانات | `0001_public_gamma_corps.sql` و`0002_violet_scrambler.sql` و`0003_silly_unicorn.sql` مطبقة بنجاح. لا يمكن فرض مشغلي منع تعديل/حذف سجل التدقيق في TiDB Serverless لأن المشغلات غير مدعومة؛ الفجوة موثقة. |
| حالة النشر | النشر التلقائي مفعّل عند كل نقطة تحقق؛ آخر نقطة تحقق منشورة هي `98ff055d`، وهذه الدفعة بانتظار حفظ نقطة تحقق جديدة. |
| التحقق البصري | فحص المسارات باستخدام مستأجر غير موجود أظهر حالة تحميل أولية فقط ثم رد API متوقع `400 BAD_REQUEST`؛ لذلك لم يُعتمد كدليل للبيانات الحية. تحقق العرض المنضبط تم باختبار خادمي مع بيانات ممررة صراحة، وتبقى مراجعة حساب مستأجر مصرح به مطلوبة عند توفره. |
| الإجراء التالي الدقيق | إعداد قاعدة اختبار مستقلة وكتابة اختبار تكامل يثبت العزل بين مستأجرين والمسار المشروع للكتابات المؤهلة خارج محاكاة قاعدة البيانات. |
