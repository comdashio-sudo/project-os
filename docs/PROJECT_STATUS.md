# حالة مشروع PROJECT OS

| الحقل | الحالة الحالية |
|---|---|
| المرحلة الحالية | Phase 2 — سجلات التحكم والحوكمة، بعد تأسيس النواة متعددة المستأجرين ومستويات Level 1–3 |
| الوحدة الحالية | إدارة المستأجرين؛ اكتمل اختيار مستخدم موجود عبر بحث بالبريد مطابق ومحدود، وإدارة الأدوار المخصصة عبر الإنشاء والتحديث والإسناد والإلغاء مع النطاقات. البحث والكتابة محميان بعضوية فعالة وحزمة EXECUTIVE وصلاحية `tenant.manage`؛ تمنع المسارات تعديل أو إلغاء دور المنفذ نفسه، وتمنع تحديث الأدوار النظامية، وتحصر صلاحيات الدور في كتالوج منتجه، وتتحقق خادميًا من ملكية المحفظة والبرنامج والمشروع للمستأجر قبل قبول النطاق. |
| أعمال مكتملة | تدقيق مستقل، مستودع GitHub خاص مستقل، توثيق البداية، مخطط الشركات والعضويات والأدوار والصلاحيات والاشتراكات والاستحقاقات وسجل التدقيق، ترحيلات ضوابط المشروع، إنشاء مساحة مستأجر فعلي، حاسبة EVM مركزية، محرك صحة المشروع، إجراءات المشاريع ولقطات EVM المحمية، وحارس WBS موحد لمسارات الميزانية والتكلفة والتقدم. أضيفت شاشة Level 3 محمية، ولوحتا Level 1 وLevel 2 بقراءات مقيّدة بالاستحقاق، وسجل PMO تفاعلي ثنائي اللغة للمخاطر والقضايا والإجراءات. كما أضيفت مسارات إنشاء المخاطر والقضايا والإجراءات والقرارات مع فحص استحقاق ونطاق المشروع وكتابة تدقيقية ذرية. نموذج الإجراء يعرض الإجراءات غير المكتملة وغير الملغاة فقط، مع ترجمة الأولويات، وحقل عدد الإجراءات المفتوحة. كما أُصلحت رسالة حفظ القرار التنفيذي وحالة غياب المشاريع. وتضمن Level 3 الآن سجلًا للأنشطة بقراءة محمية ضمن المشروع، وإنشاء محمي بحزمة PROJECT وصلاحية `project.write` ونطاق المشروع، وربط WBS اختياريًا يتحقق من النطاق، ورفض تاريخ نهاية يسبق البداية، وكتابة تدقيقية ذرية. كما يتيح مسار EVM المحسوب تجميع PV وEV وAC وBAC من مصادر محددة وحفظ اللقطة والسجل التدقيقي ذريًا، مع عرض عدادات مصدر البيانات في الواجهة. واكتمل `tenant.assignMember`: الحراسة تتطلب عضوية فعالة وحزمة EXECUTIVE وصلاحية `tenant.manage`، وتمنع إسناد دور للمنفذ نفسه، وتتحقق من المستخدم والدور والنطاق، ثم تكتب العضوية المدعوة وإسناد الدور وسجل التدقيق في معاملة واحدة. ويكملها `tenant.findAssignableUser` الذي يتطلب الحراسة ذاتها، ويبحث بالبريد المطابق فقط، ويعيد حقل الهوية الأدنى لمستخدم غير منضم للمستأجر؛ لا يعرض المستخدم إن كانت له عضوية قائمة. كما أضيف `tenant.createRole`: يتحقق من فريدة رمز الدور ضمن المؤسسة وتوافق جميع الصلاحيات المختارة مع منتج الدور وكتالوج الصلاحيات، ثم يكتب الدور وعلاقاته وسجل التدقيق في معاملة واحدة. وتعرض واجهة الإدارة نموذجًا ثنائي اللغة لإنشاء الدور واختيار الصلاحيات المتوافقة. وأضيف `tenant.assignMembershipRole`: يتحقق من أن العضوية والدور ينتميان للمستأجر، ومن صحة النطاق، ويرفض أي تعديل لدور المنفذ ذاته أو إعادة نفس الإسناد، ثم يكتب تعيين الدور وسجل التدقيق في معاملة واحدة. وتعرض واجهة الإدارة نموذجًا ثنائي اللغة يختار العضوية والدور والنطاق مع رسائل نجاح وخطأ آمنة وتحديث قراءة الإدارة. |
| العمل الجاري | أضيفت نواة الدعوات: ترحيل `0004_violet_bedlam.sql` مطبق، ومسار `tenant.createInvitation` يحفظ بصمة رمز قبول عشوائي فقط، ويربط البريد والدور والنطاق ومدة سبعة أيام وسجل التدقيق. ما زالت واجهة عرض الرابط لمرة واحدة ومسار قبول الدعوة وإرسال البريد عناصر معلقة صراحة. |
| التعريب | طبقة لغة مركزية تضبط `lang` و`dir` وتحفظ الاختيار؛ زر اللغة حاضر في رؤوس الواجهات. تضيف طبقة API رموز أخطاء ورسائل آمنة بالعربية والإنجليزية، وتعرض مساحة العمل وسجل المشاريع وحاسبة EVM الرسالة بحسب اللغة الحالية. |
| الاختبارات الفاشلة | لا توجد؛ نجح 81 اختبارًا ضمن ثمانية ملفات، وفحص TypeScript والبناء الإنتاجي في هذه الدفعة. إضافة إلى أدلة RBAC السابقة، يثبت اختبار API أن إنشاء دعوة لمستأجر بلا عضوية فعالة يُرفض قبل فحص البريد أو الدور أو الكتابة. |
| المشكلات المثبتة | أصلح توافق تجميع `Set`، وبنية JSX لمساحة العمل، وفحص نطاق WBS العابر للمشروع، وإظهار رسائل الخادم الخام في واجهات التشغيل. |
| العمل المعلق | اختبار تكامل حقيقي لقاعدة البيانات مستقل عن المحاكاة، ودعوات البريد وإدارة إنشاء/تحديث/إلغاء الأدوار والنطاقات، والمستندات وسير العمل، وبقية الوحدات الموضحة في `todo.md`. |
| ترحيلات قاعدة البيانات | `0001_public_gamma_corps.sql` و`0002_violet_scrambler.sql` و`0003_silly_unicorn.sql` و`0004_violet_bedlam.sql` مطبقة بنجاح. لا يمكن فرض مشغلي منع تعديل/حذف سجل التدقيق في TiDB Serverless لأن المشغلات غير مدعومة؛ الفجوة موثقة. |
