# حالة مشروع PROJECT OS

| الحقل | الحالة الحالية |
|---|---|
| المرحلة الحالية | Phase 2 — سجلات التحكم والحوكمة، بعد تأسيس النواة متعددة المستأجرين ومستويات Level 1–3 |
| الوحدة الحالية | تجميع EVM التشغيلي في Level 3؛ أضيف التقاط لقطة محسوبة قابلة للتتبع من السجلات، وعرض مصدرها، وتنتقل الدفعة التالية لاختبار تكامل حي بقاعدة مستقلة. |
| أعمال مكتملة | تدقيق مستقل، مستودع GitHub خاص مستقل، توثيق البداية، مخطط الشركات والعضويات والأدوار والصلاحيات والاشتراكات والاستحقاقات وسجل التدقيق، ترحيلات ضوابط المشروع، إنشاء مساحة مستأجر فعلي، حاسبة EVM مركزية، محرك صحة المشروع، إجراءات المشاريع ولقطات EVM المحمية، وحارس WBS موحد لمسارات الميزانية والتكلفة والتقدم. أضيفت شاشة Level 3 محمية، ولوحتا Level 1 وLevel 2 بقراءات مقيّدة بالاستحقاق، وسجل PMO تفاعلي ثنائي اللغة للمخاطر والقضايا والإجراءات. كما أضيفت مسارات إنشاء المخاطر والقضايا والإجراءات والقرارات مع فحص استحقاق ونطاق المشروع وكتابة تدقيقية ذرية. نموذج الإجراء يعرض الإجراءات غير المكتملة وغير الملغاة فقط، مع ترجمة الأولويات، وحقل عدد الإجراءات المفتوحة. كما أُصلحت رسالة حفظ القرار التنفيذي وحالة غياب المشاريع. وتضمن Level 3 الآن سجلًا للأنشطة بقراءة محمية ضمن المشروع، وإنشاء محمي بحزمة PROJECT وصلاحية `project.write` ونطاق المشروع، وربط WBS اختياريًا يتحقق من النطاق، ورفض تاريخ نهاية يسبق البداية، وكتابة تدقيقية ذرية. كما يتيح مسار EVM المحسوب تجميع PV وEV وAC وBAC من مصادر محددة وحفظ اللقطة والسجل التدقيقي ذريًا، مع عرض عدادات مصدر البيانات في الواجهة. |
| العمل الجاري | تجهيز اختبار تكامل فعلي بقاعدة بيانات اختبارية مستقلة لإثبات العزل الحقيقي خارج doubles الاختبار، ثم تفعيل إدارة أعضاء المستأجرين والأدوار والاستحقاقات عبر الواجهة. |
| التعريب | طبقة لغة مركزية تضبط `lang` و`dir` وتحفظ الاختيار؛ زر اللغة حاضر في رؤوس الواجهات. تضيف طبقة API رموز أخطاء ورسائل آمنة بالعربية والإنجليزية، وتعرض مساحة العمل وسجل المشاريع وحاسبة EVM الرسالة بحسب اللغة الحالية. |
| الاختبارات الفاشلة | لا توجد؛ نجح 51 اختبارًا ضمن ثمانية ملفات، وفحص TypeScript والبناء الإنتاجي في هذه الدفعة. يغطي اختبار العرض الخادمي نموذج وسجل الإجراءات بالعربية والإنجليزية، وإرشاد غياب المشروع ورسالة حفظ القرار، ونموذج وجدول الأنشطة وحالة النشاط باللغتين، وواجهة التقاط EVM المحسوب. تثبت اختبارات مجال EVM التشغيلي مصادر PV وEV وAC وBAC والتصفية الزمنية وحالات الفراغ، ويثبت اختبار API حجب المسار عند غياب استحقاق PROJECT. |
| المشكلات المثبتة | أصلح توافق تجميع `Set`، وبنية JSX لمساحة العمل، وفحص نطاق WBS العابر للمشروع، وإظهار رسائل الخادم الخام في واجهات التشغيل. |
| العمل المعلق | اختبار تكامل حقيقي لقاعدة البيانات مستقلة عن المحاكاة، اختبارات السماح التشغيلية، تجميع PV/EV/AC الفعلي من السجلات، الجدولة والأنشطة، واجهات الإجراءات والقرارات، والمستندات وسير العمل. |
| ترحيلات قاعدة البيانات | `0001_public_gamma_corps.sql` و`0002_violet_scrambler.sql` و`0003_silly_unicorn.sql` مطبقة بنجاح. لا يمكن فرض مشغلي منع تعديل/حذف سجل التدقيق في TiDB Serverless لأن المشغلات غير مدعومة؛ الفجوة موثقة. |
| حالة النشر | النشر التلقائي مفعّل عند كل نقطة تحقق؛ آخر نقطة تحقق منشورة هي `c82d8f27`، وهذه الدفعة بانتظار حفظ نقطة تحقق جديدة. |
| التحقق البصري | فحص المسارات باستخدام مستأجر غير موجود أظهر حالة تحميل أولية فقط ثم رد API متوقع `400 BAD_REQUEST`؛ لذلك لم يُعتمد كدليل للبيانات الحية. تحقق العرض المنضبط تم باختبار خادمي مع بيانات ممررة صراحة، وتبقى مراجعة حساب مستأجر مصرح به مطلوبة عند توفره. |
| الإجراء التالي الدقيق | إعداد قاعدة اختبار مستقلة وكتابة اختبار تكامل يثبت العزل بين مستأجرين والمسار المشروع للكتابات المؤهلة خارج محاكاة قاعدة البيانات، ثم تفعيل إدارة أعضاء المستأجرين والأدوار والاستحقاقات عبر الواجهة. |
