# بروتوكول القبول اليدوي للوصول وقارئ الشاشة

**الحالة:** جاهز للتنفيذ — غير منفذ حتى الآن.  
**العلاقة بسجل الأدوار:** يستكمل هذا البروتوكول [PILOT_ROLE_ACCEPTANCE.md](./PILOT_ROLE_ACCEPTANCE.md)، ولا يستبدل اختبار MySQL/TiDB أو قبول الأدوار الآلي.

> نفّذ البروتوكول في جلسة Pilot حقيقية فقط. لا تضع كلمات مرور أو رموز OAuth أو بيانات عميل في أي سجل اختبار. استخدم معرّف المستخدم المقنع، اسم المتصفح، الوقت UTC، ومعرّف سجل التدقيق عند وجوده.

## التحضير

| المعرف | الإعداد المطلوب | معيار النجاح |
|---|---|---|
| `PRE-01` | أربعة حسابات مستقلة: EXECUTIVE وPMO وPROJECT ومنخفض الصلاحية، ضمن مستأجر Pilot محدد. | لا يتشارك حسابان جلسة أو دورًا مؤقتًا. |
| `PRE-02` | مشروع Pilot واحد مع بيانات اختبار قابلة للحذف، ومجال PMO ومجال EXECUTIVE مصرحان للحسابين المناسبين. | يمكن التحقق من الأثر وسجل التدقيق بلا بيانات عميل حقيقية. |
| `PRE-03` | سطح مكتب حديث وجوال حديث، وقارئ شاشة واحد على الأقل (NVDA/Chrome أو VoiceOver/Safari). | يوثق اسم النظام والمتصفح وقارئ الشاشة وإصداره عند الإمكان. |
| `PRE-04` | نسخة التطبيق المنشورة المطابقة لنقطة التحقق المراد اعتمادها. | يسجل رقم النسخة أو وقت النشر قبل البدء. |

## سيناريوهات الأدوار

| المعرف | الهوية | الإجراء | النتيجة المتوقعة | الدليل المطلوب |
|---|---|---|---|---|
| `ROLE-EX-01` | EXECUTIVE | افتح Level 1 وأنشئ قرارًا في مشروع Pilot المصرح. | يظهر القرار في اللوحة أو السجل وينشأ تدقيق `decision.created`. | لقطة أو رابط داخلي مقنّع، ومعرّف التدقيق. |

| `ROLE-PM-01` | PMO | افتح Level 2 وأنشئ مخاطرة أو إجراءً في مشروع Pilot. | يظهر السجل وينشأ `pmo.risk_created` أو تدقيق الإجراء الموافق. | لقطة ومعرّف التدقيق. |

| `ROLE-PR-02` | PROJECT | حاول مشروعًا عابرًا أو وظيفة PMO غير مصرح بها. | منع موطن بلا أثر. | لقطة ورسالة وغياب أثر. |
| `ROLE-LO-01` | منخفض الصلاحية | افتح روابط Level 1 وLevel 2 وLevel 3 المتوقعة. | لا تتاح أي كتابة محمية ولا تظهر بيانات خارج النطاق. | لقطات أو تسجيل نتائج لكل مستوى. |
