# PROJECT OS — دليل الاستخدام | User Guide

## قبل البدء | Before you start

**العربية:** PROJECT OS منصة تشغيل وحوكمة للمشاريع. يبدأ الاستخدام من الشركة ثم المشروع ثم مساحة العمل المناسبة للدور. لا تدخل ملفًا أو تستورد Excel قبل التأكد من المستأجر والمشروع والقالب.

**English:** PROJECT OS is a governed project-operating platform. Work starts at company scope, continues to the project, and then opens the workspace appropriate to the user’s role. Never import an Excel file before confirming the tenant, project, and approved template.

| المستوى | ما يراه المستخدم | أفضل نقطة بداية |

## 3. دورة الاستخدام اليومية | Daily operating cycle

1. **افتح لوحة المستوى المناسب.** لا تبدأ بالبحث في كل سجل؛ استخدم بطاقة الاستثناء أو الاختصار المحكوم.
2. **حدد المشروع والنطاق.** يجب أن يطابق السجل المشروع والمستأجر المصرح بهما.
3. **أدخل الحد الأدنى من البيانات المطلوبة.** اترك الحقول غير المعروفة فارغة بدل تخمين قيمة.
4. **تحقق من الأثر.** بعد الحفظ، افتح القراءة أو المؤشر الذي يجب أن يتغير. نجاح الزر وحده ليس دليلًا على أثر كامل.
5. **تابع التدقيق.** العمليات الحساسة يجب أن تنتج سجل تدقيق داخل المعاملة نفسها.
6. **أغلق أو صعّد.** استخدم انتقال الحالة المسموح بدل تعديل حالة مخفية أو تجاوز سير العمل.

## 4. المواد والمشتريات | Materials and procurement

**العربية:** أنشئ طلب مادة مرتبطًا بالمشروع وWBS/النشاط عندما يكون ذلك متاحًا. راجع طلب التوريد ثم أمر الشراء ثم الاستلام. لا تسجل حركة مخزون أو تكلفة من شاشة الاستلام وحدها. الصرف يجب أن يتحقق من الرصيد المشتق ومن المشروع/WBS، ويمنع الرصيد السالب.

**English:** Create a material request linked to the project and WBS/activity when available. Review the requisition, then the purchase order, then the receipt. Do not infer a stock or cost movement from the receipt screen alone. An issue must validate derived stock and project/WBS scope and must prevent negative inventory.

## 5. الموظفون والرواتب وKPI | Workforce, payroll and KPIs

**العربية:** سجّل الموظف أو المورد ضمن النطاق المسموح، ثم اربط التخصيص بالمشروع والدور والفترة. افصل بين إدخال الأجر واعتماده وقراءة البيانات المحمية. KPI يجب أن يرتبط بمصدر رقمي وتعريف وفترة ومالك، ولا يُنشأ من تقييم انطباعي فقط.

**English:** Create the employee or resource within the authorized scope, then link allocation to project, role, and period. Separate payroll entry, approval, and protected salary access. Every KPI should have a numeric source, definition, period, and owner; it must not be a purely subjective score.

## 6. Excel والاستيراد | Excel and imports

1. استخدم القالب المعتمد للقسم فقط. لا يوجد استيراد Excel عام لأي شكل من البيانات.
2. استخدم ورقة واحدة ونوع بيانات واحدًا لكل ملف ما لم يذكر القالب غير ذلك.
3. املأ الحقول الإلزامية كما هي، ولا تغيّر أسماء الأعمدة.
4. راجع المعاينة والتحويلات ومفاتيح الأعمال قبل التأكيد.
5. ارفض الملف عند الأعمدة غير المعروفة أو المفاتيح المكررة أو الغموض.
6. بعد التأكيد، راجع السجل والأثر في الشاشة والقراءة التابعة.

**English:** Use only the approved template for the target record. Use one sheet and one data type per file unless the template says otherwise. Keep required headers unchanged, review preview and conversions, reject unknown columns/duplicates/ambiguity, confirm explicitly, and verify the audit and downstream effect.

## 7. ما الذي لا يجب فعله | What not to do

| لا تفعل | السبب |
|---|---|
| لا تستخدم فواتير اشتراك المنصة لفواتير المشروع أو المقاول. | هما كيانان تجاريان مختلفان. |
| لا تعتمد على وجود بريد OAuth باعتباره ملكية مؤكدة. | لا يوجد دليل `email_verified` معتمد حاليًا. |
| لا تدخل بيانات عبر SQL لتجاوز الواجهة في قبول المستخدم. | قبول الأدوار يتطلب مسار المستخدم الحقيقي. |
| لا تعتبر شاشة فارغة دليلًا على عدم وجود بيانات. | قد يكون السبب فشل مصدر أو رفض وصول. |
| لا تُدخل بيانات حقيقية في بيئة الاختبار. | استخدم مستأجرًا ومشروعًا معزولين. |

## 8. استكشاف الأخطاء | Troubleshooting

إذا ظهرت رسالة رفض، تحقق من الشركة والمشروع والحزمة والصلاحية والدور بدل إعادة المحاولة عشوائيًا. إذا ظهر قسم فارغ، تحقق من حالة المصدر: تحميل، فارغ، خطأ، أو جزئي. إذا نجح الحفظ ولم يظهر الأثر التابع، سجّل الحالة ولا تكرر العملية قبل التحقق من سجل التدقيق والمعاملة.

## 9. حدود الحالة الحالية | Current limits

اختبارات الوحدة والواجهة وفحص الأنواع والبناء وتغطية tRPC ومنح `audit_logs` نجحت في آخر بوابة محلية موثقة. اختبار النسخ والاسترجاع المنطقي لمستأجر معزول نجح. أما التكامل الشامل على TiDB وقبول الأدوار الحي فهما غير متحققين حاليًا، لذلك لا ينبغي تقديمهما كقبول نهائي أو كضمان Pilot.
