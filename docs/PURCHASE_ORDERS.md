# نواة أوامر الشراء

## النطاق

يوثق سجل أوامر الشراء في **Level 3** أمرًا تشغيليًا داخل مشروع واحد. يتضمن السجل رقم أمر فريدًا داخل المشروع واسم المورد وتاريخ الأمر والقيمة والعملة والملخص وحالة دورة العمل. لا يرسل السجل طلب دفع ولا يخزن فاتورة أو مخزونًا، ولا يربط نفسه تلقائيًا بعقد أو التزام.

## الحراسة ودورة الحالة

| العملية | الفرض الخادمي |
|---|---|
| القراءة | عضوية المستأجر، حزمة PROJECT، صلاحية `project.read`، وملكية المشروع. |
| الإنشاء | عضوية المستأجر، حزمة PROJECT، صلاحية `project.write`، وملكية المشروع. |
| الانتقال | اختيار أمر الشراء وفق المعرّف والمستأجر والمشروع، ثم التحقق من خريطة انتقال ثابتة. |
| التدقيق | كل إنشاء أو انتقال يكتب سجل تدقيق ضمن المعاملة نفسها. |

```text
draft → submitted → approved → issued
                    └→ cancelled
         approved ────→ cancelled
```

## التحقق المثبت

يثبت تكامل MySQL/TiDB رفض إنشاء أمر شراء أو انتقاله في مشروع مستأجر آخر قبل الكتابة، ثم إنشاء أمر بقيمة `12500.50 USD` وانتقاله `draft → submitted → approved → issued` مع أربعة سجلات تدقيق قابلة للاستعلام. تثبت اختبارات DOM إدخال رقم الأمر والمورد والقيمة والعملة والملخص، وتمرير نطاق المشروع، وإتاحة الانتقال التالي فقط، وتعريب عنوان السجل وزر الانتقال.

## الحد الحالي

لا يربط الإصدار أمر الشراء تلقائيًا بعقد أو التزام أو فاتورة أو مخزون، ولا ينفذ دفعات خارجية. تتطلب هذه الروابط معاملاتها وحراسات نطاقها المستقلة.
