# نواة أوامر الشراء

## النطاق

يوثق سجل أوامر الشراء في **Level 3** أمرًا تشغيليًا داخل مشروع واحد. يتضمن السجل رقم أمر فريدًا داخل المشروع واسم المورد وتاريخ الأمر والقيمة والعملة والملخص وحالة دورة العمل. لا يرسل السجل طلب دفع ولا يخزن فاتورة أو مخزونًا، ولا يربط نفسه تلقائيًا بعقد أو التزام.

## الحراسة ودورة الحالة

| العملية | الفرض الخادمي |
|---|---|
| القراءة | عضوية المستأجر، حزمة PROJECT، صلاحية `project.read`، وملكية المشروع. |
| الإنشاء | عضوية المستأجر، حزمة PROJECT، صلاحية `project.write`، وملكية المشروع. |
| الانتقال | اختيار أمر الشراء وفق المعرّف والمستأجر والمشروع، ثم التحقق من خريطة انتقال ثابتة. |
| التدقيق | كل إنشاء أو انتقال يكتب سجل تدقيق ضمن المعاملة نفسها. |

```text
draft → submitted → approved → issued → received
                    └→ cancelled
         approved ────→ cancelled
```

## ربط العقد والالتزام والاستلام

يجوز ربط أمر الشراء اختياريًا بعقد وبالتزام في المشروع ذاته. لا يثق الخادم بالمعرّفات القادمة من الواجهة: يعيد اختيار العقد والالتزام ضمن المستأجر والمشروع، ويرفض أي مرجع مفقود أو عابر. وعند تمرير الرابطين معًا، يرفض الخادم التزامًا مرتبطًا بعقد مختلف. لا يصل أمر صادر إلى `received` إلا عبر انتقال الخادم، الذي يكتب `receivedAt` بتوقيت الخادم ويسجل الأثر في سجل التدقيق داخل المعاملة نفسها.

## التحقق المثبت

يثبت تكامل MySQL/TiDB رفض إنشاء أمر شراء أو انتقاله في مشروع مستأجر آخر قبل الكتابة، ورفض عقد أو التزام من مشروع مستأجر آخر، ورفض التزام لا يطابق العقد المحدد. ثم يثبت إنشاء أمر مرتبط بعقد والتزام مملوكين وانتقاله `draft → submitted → approved → issued → received` بقيمة `12500.50 USD`، مع وقت استلام وخمسة سجلات تدقيق قابلة للاستعلام. تثبت اختبارات DOM إدخال رقم الأمر والمورد والقيمة والعملة والملخص واختيار العقد والالتزام، وإتاحة الاستلام التالي فقط، وتعريب عنوان السجل وزر الانتقال.

## الحد الحالي

لا ينشئ الإصدار فاتورة أو قيد تكلفة أو دفعة خارجية أو حركة مخزون تلقائيًا عند الاستلام. تتطلب هذه القيود المالية اللاحقة نقطتها التقاربية وحراستها المستقلة.
