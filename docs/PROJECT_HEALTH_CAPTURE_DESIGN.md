# تصميم التقاط صحة المشروع

تعتمد لقطة الصحة الحالية على أحدث لقطة EVM محفوظة للمشروع، وعلى المخاطر المفتوحة ذات الأولوية المرتفعة أو الحرجة، وعلى الإجراءات غير المكتملة التي تجاوزت تاريخ استحقاقها، وعلى RFI وNCR وملاحظات HSE المفتوحة والمتأخرة. لا توجد بعد كيانات للموافقات التشغيلية؛ لذلك يمرر مصدرها بصفر صريح إلى المحرك، ولا تدّعي الواجهة أنها قاستها.

| المصدر | طريقة القراءة | استخدامه في المحرك | الحد الحالي |
|---|---|---|---|
| EVM | أحدث لقطة للمستأجر والمشروع | `CPI` و`SPI` و`EAC` و`BAC` | لا لقطة يعني مؤشرات مالية غير معروفة |
| المخاطر | مفتوحة وعالية أو حرجة | `highRiskCount` | لا يحسب المخاطر المغلقة أو المتوسطة |
| الإجراءات | غير مكتملة وغير ملغاة ومستحقة قبل وقت الخادم | `overdueActionCount` | الوقت من الخادم فقط |
| الموافقات | لا جدول في المخطط | صفر صريح | يظهر هذا الحد في بيانات المصدر ولا يتحول إلى ادعاء |
| RFI | مفتوح وغير ملغى ومستحق قبل وقت الخادم | `overdueRfiCount` | لا يحسب RFI المغلق أو الملغى |
| NCR | مفتوح أو قيد التحقيق وغير ملغى ومستحق قبل وقت الخادم | `overdueNcrCount` | لا يحسب NCR المغلق أو الملغى |
| HSE | مفتوح وغير مغلق أو ملغى ومستحق قبل وقت الخادم | `overdueHseCount` | لا يحسب الملاحظة المغلقة أو الملغاة |

يستلزم الالتقاط حزمة `PROJECT` وصلاحية `project.write` ونطاق المشروع. تكتب الخدمة لقطة الصحة وسجل التدقيق في معاملة واحدة. تتطلب القراءة `project.read` والنطاق نفسه. يشمل دليل القبول رفض غياب العضوية أو الاستحقاق، ورفض مشروع خارج المستأجر، والسماح الذري مع سجل التدقيق، وعرض الحدود ومخرجات المحرك بالعربية والإنجليزية.

يثبت تكامل MySQL/TiDB الآن قراءة المصادر الحية قبل كتابة اللقطة: ينشئ لقطة EVM تشغيلية، ومخاطرة مفتوحة بدرجة 16، وإجراءً مفتوحًا متأخرًا، وRFI وNCR وملاحظة HSE متأخرة، ثم يلتقط الصحة ضمن المشروع المصرح. يثبت الدليل `latestEvmFound=true` و`highRiskCount=1` و`overdueActionCount=1` و`overdueRfiCount=1` و`overdueNcrCount=1` و`overdueHseCount=1` وسجل تدقيق صحة المشروع. تنظف الحالة مصادرها وإشعاراتها ولقطاتها قبل المسارات الشقيقة.
