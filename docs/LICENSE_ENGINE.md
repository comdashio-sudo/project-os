# نواة التجارة والترخيص

## الحالة قبل التوسعة

يمتلك PROJECT OS اشتراكًا واحدًا لكل مستأجر و`tenant_entitlements` للمنتجات الثلاثة. يفرض الخادم المنتج داخل إجراءات الأعمال، لكنه لا يميز الخطة أو الميزة أو حدود المقاعد والمشاريع والتخزين والذكاء والاستيراد والتصدير وMaster Plan. كذلك لا يمثل حالة التعليق أو فترة السماح صراحةً.

## التنفيذ المنجز

أضيفت طبقة ترخيص فوق الاشتراك الحالي، لا بديلًا عنه. يضيف الترحيل `0016_colorful_scarecrow.sql` جداول `commercial_plans` و`commercial_features` و`plan_feature_entitlements` و`tenant_licenses` و`tenant_license_feature_overrides`، بينما يوسع `0017_groovy_sleeper.sql` حالات الاشتراك إلى التجربة والنشاط والتأخر والتعليق والإلغاء والانتهاء وفترة السماح.

| المجال | التنفيذ المفروض خادميًا |
|---|---|
| كتالوج الخطط | خطط قياسية للحزم EXECUTIVE وPMO وPROJECT وتركيباتها وALL-IN-ONE، مع ميزات Master Plan والاستيراد والتصدير. |
| التفعيل اليدوي | مسؤول المنصة فقط ينشئ أو يحدّث الرخصة، ويحدّث الاشتراك والاستحقاقات وسجل التدقيق ضمن معاملة واحدة. |
| دورة الحالة | خريطة انتقال صريحة تمنع القفزات؛ التعليق أو الإلغاء يعطل استحقاقات المنتج، وإعادة التفعيل تعيدها. |
| تجاوز الميزة | مسؤول المنصة فقط يضبط تفعيل الميزة وحدها لكل رخصة، مع سجل تدقيق. |
| الفرض التشغيلي | Master Plan يطلب الميزة النشطة، ويمنع إنشاء خطة أو كيان مكاني عند بلوغ الحد الممنوح. يفرض محرك العضوية مقاعد الرخصة الفعالة داخل المعاملة عند إسناد عضو أو إصدار دعوة أو قبولها. ويمنع إنشاء مشروع جديد عند بلوغ `PROJECT_LIMIT` الفعال. |
| القراءة | مسؤول المؤسسة يقرأ رخصة مؤسسته؛ مسؤول المنصة يقرأ الرخصة لإدارتها حتى إن كانت حزمة المستأجر PROJECT فقط. |

تعرض الصفحة `/licensing/:tenantId` الرخصة الحالية والحدود وتغيير الحالة، وتعرض نموذج التفعيل أو الترقية فقط حين ينجح فحص مسؤول المنصة. تعرض الواجهة الرسائل العربية والإنجليزية عبر خريطة الأخطاء ولا تمرر نص الخادم الخام.

## أدلة التحقق

يثبت تكامل MySQL/TiDB المعزول كتالوج الخطط، وتفعيل رخصة PROJECT يدويًا، وقراءة الرخصة، ورفض مستخدم بلا عضوية عند قراءة مستأجر آخر، وتجاوز حد `MASTER_PLAN` بصفر، وتعليق الرخصة ومنع وصول المنتج، ثم إعادة التفعيل واستعادة الاستحقاقات. يسجل الدليل خمسة أحداث ترخيصية قبل الاستعادة. كما يثبت اختبار DOM أن شاشة التراخيص تمرر حد Master Plan ومعرّف الرخصة ومعرّف المستأجر إلى عقد التجاوز المحمي.

يثبت دليل المقاعد رخصة `ALL_IN_ONE_STANDARD` بمقعدين، ثم يحجز دعوة معلقة المقعد الثاني ويرفض إسناد عضو مباشر ثالث. يخفض الدليل الرخصة إلى مقعد واحد فيرفض قبول الدعوة مع بقاء الدعوة معلقة وغياب العضوية وتدقيق القبول، ثم يعيد مقعدين فينجح القبول ويثبت العضوية النشطة وسجلا دعوة/قبول قابلان للتحقق. يتضمن `PROJECT_OS_LICENSE_SEAT_LIMIT_EXCEEDED` رسالتين عربيتين وإنجليزيتين، ويطبق الحارس فقط إن وجدت رخصة في حالة `trialing` أو `active` أو `grace_period`؛ فلا يفرض حدًا مصطنعًا على مستأجر لا يملك رخصة مفعلة بعد.

تضيف الخطة ميزة `PROJECT_LIMIT` بحد افتراضي 20 مشروعًا، وقابلة للتجاوز لكل رخصة من وحدة التراخيص. قبل كتابة مشروع جديد، تهيئ الخدمة الكتالوج ثم تقفل الرخصة الفعالة ضمن المعاملة وتقرأ التجاوز أو حد الخطة وتعد مشاريع المستأجر. يثبت تكامل MySQL/TiDB حدًا قدره 1 مع مشروع قائم ورفضًا قبل السجل التشغيلي والتدقيق، ثم حدًا قدره 2 وإنشاء مشروع مصرح مع سجل `project.created`، ثم تنظيف البيانات وإعادة الحد. لا يمنع الحارس مشروعًا في مستأجر بلا رخصة فعالة، اتساقًا مع مسار تهيئة العميل قبل التفعيل.

ويثبت التكامل الآن تحويل رخصة المستأجر إلى `ALL_IN_ONE_STANDARD` بحالة `active` ثم قراءة الرخصة الفعالة بالرمز الجديد. كما يثبت أن الحزمة لا تتجاوز RBAC: تعيد الملاحة عناصر EXECUTIVE وPROJECT المصرح بها، وتبقى `pmo-controls` مخفية عندما لا تتوفر صلاحية PMO المناسبة.

تفرض مسارات `dataImports.analyze` و`dataImports.confirm` وقراءة سجل الاستيراد عند مستوى المشروع ميزة `DATA_IMPORT` بعد فحص المنتج والصلاحية والنطاق وقبل التخزين أو الكتابة. يمثل حد الاستيراد عدد سجلات التحليل المسجلة داخل المشروع. ويفرض مسار `dataImports.export` ميزة `DATA_EXPORT` قبل بناء الملف أو كتابة سجل التصدير؛ يمثل حد التصدير الحد الأعلى لصفوف ملف واحد. يثبت التكامل تعطيل الميزتين والحد الصفري وغياب سجل استيراد أو تصدير جديد، ثم يعيد التهيئة الآمنة للمسارات اللاحقة.

## حدود مقصودة

لا توجد مفاتيح Stripe أو Tap أو مزود آخر، ولذلك لا تنفذ هذه الدفعة صفحة دفع أو تحقق webhook أو تخزين بيانات دفع. يقتصر المسار على تفعيل يدوي قابل للتدقيق وتغيير حالة الرخصة. تطبق الدفعة حد المقاعد وحد المشاريع، لكن حدود التخزين والذكاء لم تُفرض بعد في مسارات الأعمال؛ ولا تُعلن كمنفذة. لا يمثل إعداد زمن الانتهاء أو فترة السماح مهمة زمنية تلقائية، ويجب ربطه بمزود دفع أو مهمة مجدولة محكومة في دفعة لاحقة.
