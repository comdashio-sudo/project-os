# دليل الدفعة 2.4 — طلب المواد من الموقع

**الحالة:** `PROVEN` محليًا قبل الالتزام. توسّع الدفعة سجل `procurement_requisitions` القائم بدل إنشاء سجل أو شاشة موازية. لا يمكن ربط أمر شراء إلا **بطلب معتمد غير مربوط** وبأمر شراء قائم من المستأجر والمشروع نفسيهما وحالته `approved` أو `issued` أو `received`. الربط أحادي الاتجاه: لا ينشئ أمر شراء، ولا يحدّث أمرًا أو التزامًا أو تكلفة أو مخزونًا. لا تنفذ الدفعة **GRN** أو صرفًا إلى تكلفة فعلية/EVM؛ هذان اندماجان منفصلان محجوزان للبندين 2.5 و2.7 من أمر العمل الممتد.

| المتطلب | التنفيذ المثبت |
|---|---|
| طلب مواد مرتبط بالمشروع | صار إنشاء الطلب يتطلب مادة نشطة من المستأجر ووحدة قياس مطابقة للمادة، مع وصف وكمية موجبة وتاريخ احتياج. المورد يبقى اختياريًا كمورد مقترح، فلا تتحول حاجة الموقع إلى أمر شراء أو عقد تلقائيًا. |
| WBS والنشاط | يحمل الطلب `wbsItemId` و`activityId` اختياريين. يتحقق الخادم أن كليهما من المشروع نفسه، وأن النشاط يرتبط بحزمة WBS المختارة إن وُجد الاثنان. يرفض مرجع WBS أو نشاطًا عابرًا من دون كشفه. |
| دورة الحالة | تستمر المسودة والإرسال والاعتماد/الرفض/الإلغاء. لا يدخل `partially_issued` أو `closed` عبر زر انتقال عام: تسجل حركة صرف مخزون مرتبطة بالطلب فقط، فتجعل الحالة **مصروفًا جزئيًا** أو **مغلقًا** عند بلوغ الكمية المطلوبة. يرفض الإغلاق اليدوي قبل الوفاء الكامل. |
| الربط بالمخزون | أضيف `requisitionId` اختياري إلى `warehouse_inventory_transactions`. يقبل الربط لحركة `issue` سالبة فقط، وبالمادة نفسها، ولطلب معتمد أو مصروف جزئيًا. تجمع قراءة السجل الحركات المرتبطة لتعيد الكمية المصروفة والمتبقية؛ لا تخزن رصيد صرف منفصلًا قابلًا للتعديل. |
| ربط أمر شراء قائم | يضيف الطلب `purchaseOrderId` ووقت الربط ومنفذه. يتحقق الخادم بعد حراسة العضوية والاستحقاق والصلاحية والنطاق من أن الطلب المعتمد غير مربوط ومن أن الأمر القائم في المشروع نفسه وحالته تشغيلية ضيقة (`approved`/`issued`/`received`). تكتب المعاملة تحديث الطلب وحده وسجل `procurement.requisition_purchase_order_linked`؛ لا تستدعي مسار إنشاء/انتقال أمر شراء ولا تعدل `purchase_orders` أو `commitments` أو `cost_entries` أو حركات المستودع. |
| الذرية والتدقيق | تسجل معاملة الصرف الرصيد والحركة وتحويل حالة الطلب، ثم تسجل `warehouse.inventory_recorded` و`procurement.requisition_issued` مع الكمية السابقة/المتبقية. إنشاء الطلب وانتقالاته يظلان مدققين في معاملاتهما. |
| الحراسة | تتطلب جميع القراءة والكتابة عضوية المستأجر، ومنتج `PROJECT`، وصلاحية `project.read` أو `project.write` وفق الفعل، ونطاق المشروع. يستعمل الخادم الاستعلامات المقيدة بالمستأجر والمشروع للمادة والمورد وWBS والنشاط والطلب والمستودع. |
| الواجهة | توسع `ProjectProcurement` بواجهة Dashio عربية/إنجليزية: مادة إلزامية تضبط وحدة القياس، WBS، نشاط مرشح بحسب WBS، كمية مصروفة/متبقية، وحالة الصرف. للطلب المعتمد غير المربوط فقط تعرض قائمة أوامر المشروع التشغيلية وزر ربط؛ بعد النجاح تعرض رقم الأمر المرتبط ولا تقدم إنشاء أمر جديد. لا تعرض رواتب أو بيانات PDPL، ولا تستحدث صفحة موازية. |
| الترحيلات | يضيف `0041_narrow_fallen_one.sql` روابط WBS والنشاط في الطلب، ورابط الطلب في حركة المخزون وفهرسه، ويوسع تعداد الحالة. يضيف `0042_late_hawkeye.sql` مرجع أمر الشراء ووقت/منفذ الربط ومفاتيحه وفهرسه. لأن Drizzle لم يولّد تعديل enum في 0041 ولا عمود `purchaseOrderId` في 0042 رغم تغيّر المخطط، أضيفا يدويًا بعد مراجعة SQL؛ وكلاهما إضافة متوافقة بلا حذف أو تحويل بيانات. طُبقا على MySQL/TiDB التشغيلي، ثم أعاد التوليد بلا فرق. |

## الدليل الحي والأتمتة

| الدليل | النتيجة |
|---|---|
| عزل المشروع وWBS | يثبت المشغل رفض إنشاء الطلب لمشروع عابر، ثم رفض WBS في مستأجر/مشروع آخر. |
| الاستحقاق | يعطل المشغل استحقاق `PROJECT` ويثبت رفض إنشاء الطلب بلا كتابة، ثم يعيده لمسار السماح. |
| تدفق الموقع | ينشئ WBS ونشاطًا ومادة وطلبًا، ثم يرسله ويعتمده. يستلم المخزون 12، ويصرف 5 مرتبطة بالطلب فتظهر `partially_issued` و5 مصروفة، ويرفض الإغلاق غير المكتمل، ثم يصرف 7 فيغلق الطلب تلقائيًا عند 12 و0 متبقية. |
| ربط PO والعزل | ينشئ المشغل أمر شراء قائمًا في المشروع نفسه، ويثبت رفض أمر فعلي عابر من مستأجر/مشروع آخر، ثم يعطل استحقاق `PROJECT` ويثبت أن الربط يرفض بلا كتابة، ويعيد الاستحقاق فيربط الطلب مرة واحدة ويثبت رفض إعادة الربط. |
| حصانة الأثر الاقتصادي | يلتقط المشغل قبل الربط وبعده عدد أوامر المشروع وقيمة الأمر المحدد وعدد الالتزامات وعدد التكاليف الفعلية؛ القيم الأربع متطابقة. لا يوجد أمر مكرر أو تعديل قيمة أو التزام أو تكلفة. |
| قابلية الترحيل | يشغّل المشغل نص `0042_late_hawkeye.sql` نفسه على نسخة جدول معزولة، ويتحقق من الإضافة الواحدة لمرجع الأمر وأعمدة وقت/منفذ الربط وفهرس الربط. يثبت ذلك خلو الملف النهائي من إضافة عمود مكررة وإمكان تطبيقه على مخطط نظيف. |
| التدقيق والتنظيف | يثبت المشغل موردًا وطلبًا مغلقًا وأمرًا مرتبطًا وحركتي صرف وستة آثار تدقيق للطلب، ثم يحذف التدقيق والحركة/الرصيد/المستودع/الطلب/الأمر/النشاط/WBS/المادة الدليل قبل المسارات الشقيقة كي لا تتأثر EVM أو HSE أو التدفق النقدي. |
| واجهة | اختبار DOM يثبت إرسال المادة ووحدة القياس وWBS والنشاط، واختيار أمر شراء قائم وإرسال `linkPurchaseOrder` بالطلب والأمر نفسيهما، وعرض الصرف، والتحول العربي، وغياب بيانات الراتب. |
