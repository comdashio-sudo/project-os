# دليل الدفعة 6.هـ — مؤشرات الأداء الفردية

**الحالة:** `PROVEN` قبل الالتزام. تنفذ هذه الدفعة مؤشرات قراءة مشتقة من مصادر تشغيل موجودة؛ لا تنشئ جدول مهام أو تقييمًا موازيًا، ولا تُصدر قرارًا تأديبيًا أو تعاقديًا أو ترتيبًا عامًا.

| شرط أمر العمل | التنفيذ والدليل القابل لإعادة التشغيل |
|---|---|
| مصادر الحقيقة | يجمع الحساب الأنشطة المسندة عبر `employee_assignments`، وإجراءات العضو، وRFI وNCR وفحوص الجودة والتقارير الميدانية وطلبات المواد التي أنشأها المستخدم المرتبط اختياريًا ببطاقة الموظف. لا يخترع قيمة عند غياب مصدر، ويميز المصدر والرقم والحالة والتاريخ. |
| المعادلة الشفافة | `assigned` هو كل مصدر غير مستبعد؛ `completed` هو كل سجل له `completedAt`؛ `overdue` سجل مفتوح تجاوز `dueAt`؛ نسبة الإنجاز في الموعد هي المنجز في/قبل الموعد على المنجز ذي الموعد؛ وزمن الاستجابة متوسط `completedAt - createdAt`. يعيد الخادم نص المعادلة وعداد كل نوع مصدر ووقت الحساب. |
| الاستبعاد المحافظ | يحفظ `employee_performance_exclusions` سببًا إلزاميًا لا يقل عن 10 أحرف، ونوع المصدر ومعرّفه والموظف والمشروع والمنشئ. لا يقبل الخادم سجلًا خارج مؤشر الموظف ولا التكرار، ويكتب `employee.performance_exclusion_created` في المعاملة نفسها. لا يمحو المصدر التشغيلي. |
| الاعتراض المحكوم | يستطيع الموظف المرتبط بحسابه تقديم اعتراض نصي على مؤشره فقط. يمر الاعتراض بـ`submitted → under_review → resolved/rejected`، ويتطلب الحل أو الرفض ملاحظة معالجة غير فارغة لا تقل عن 10 أحرف **في الخادم**، لا في الواجهة وحدها. يثبت المشغل الحي رفض طلب API بلا ملاحظة مع بقاء الحالة وعدد سجلات التدقيق كما هما، ثم نجاح الحل بالملاحظة. يحفظ `employee_performance_objections` النتيجة والمراجع والتاريخ، ويكتب التدقيق ذريًا. لا يقبل المدير اعتراضًا بالنيابة عن الموظف. |
| RBAC ونطاق الرؤية | تمنح `project.performance.read_own` لكل دور تشغيلي لقراءة المؤشر الذاتي فقط. تمنح `project.performance.manage` لمدير المشروع وHR لعرض الموظف ضمن نطاق مشروعهما وإنشاء الاستبعاد ومراجعة الاعتراض. يرفض الخادم الموظف غير المسند إلى المشروع حتى لو كان في المستأجر نفسه، ويمنع أي كشف لراتب أو هوية PDPL. |
| واجهة ثنائية اللغة | تعرض `/projects/:tenantId/:projectId/my-performance` مؤشر الموظف الشخصي والمصادر والمعادلة والوقت والاعتراض. تعرض `ProjectWorkforce` لمدير المشروع اختيار العامل المسند، والمؤشرات ضمن المشروع، والاستبعاد الموثق، واعتراضاته وانتقالاتها. لا توجد قائمة ترتيب عام ولا رواتب. |
| نموذج البيانات والترحيل | يضيف `0039_aromatic_doctor_faustus.sql` جدولي الاستبعاد والاعتراض، وفهارس قراءة ومفاتيح خارجية قصيرة (`epe_*` و`epo_*`) متوافقة مع MySQL/TiDB. طُبق على قاعدة التشغيل عبر ترحيل غير هدام، ثم أعاد Drizzle `No schema changes`. |

## الدليل الأمني والحي

| حالة مثبتة | النتيجة |
|---|---|
| المستأجر/المشروع العابر | يرفض المشغل الحي طلب مؤشر لموظف في مستأجر آخر، ويرفض استبعادًا في مشروع عابر. |
| غياب استحقاق PROJECT | يعطل المشغل استحقاق PROJECT ثم يثبت رفض قراءة المؤشر وتقديم الاعتراض قبل أي أثر، ويعيد الاستحقاق لمسار السماح. |
| نطاق الموظف داخل المستأجر | ينشئ المشغل موظفًا من المستأجر نفسه غير مسند للمشروع ويثبت رفض القراءة بـ`PROJECT_OS_ASSIGNMENT_NOT_FOUND`. |
| السماح والتدقيق | يقرأ المستخدم المرتبط مؤشّره الذاتي، ثم ينشئ المدير استبعاد النشاط، ويقدم الموظف اعتراضًا. يثبت الدليل رفض حل الاعتراض بلا ملاحظة من دون تغيير حالة أو تدقيق، ثم يحل المدير الاعتراض بالملاحظة. يثبت المشغل ثلاثة سجلات تدقيق للآثار المسموحة فقط. |
| واجهة وآلة الحساب | يثبت اختبار المجال استخراج العدادات واستبعاد مصدر واحد. تثبت اختبارات DOM الصفحة الإنجليزية/العربية، وضوح عدم الأثر التأديبي، وإرسال الاعتراض الذاتي، وعرض مركز المدير بلا راتب. |
