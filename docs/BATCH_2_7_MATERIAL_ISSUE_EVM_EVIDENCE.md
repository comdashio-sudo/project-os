# دليل الدفعة 2.7 — صرف المواد إلى أعمال المشروع والتكلفة الفعلية

**الحالة:** `PROVEN` محليًا قبل الالتزام. تضيف الدفعة سجل صرف مواد محكومًا يربط **حركة صرف مخزون واحدة** بتكلفة فعلية منشورة واحدة وبـWBS إلزامي ونشاط اختياري متوافق. لا تعيد استخدام إدخال حركة المخزون العام لإنتاج أثر اقتصادي، ولا تسمح بإنشاء تكلفة منفصلة عن الصرف المادي نفسه.

| المتطلب | التنفيذ المثبت |
|---|---|
| سجل الصرف | جدول `material_issues` يحمل مراجع حركة المخزون والتكلفة الفعلية والمادة وWBS والنشاط والكمية وتكلفة الوحدة والإجمالي وتاريخ الصرف والمنفذ. يفرض فهرسان فريدان أن ترتبط حركة واحدة بتسجيل صرف واحد وتكلفة واحدة بتسجيل صرف واحد. |
| النطاق | يفرض الخادم `PROJECT` و`project.write` وعضوية المستأجر ونطاق المشروع قبل القراءة. يتحقق من المستودع النشط والمادة وWBS في المشروع نفسه؛ والنشاط، إن مرر، يجب أن يتبع WBS المحدد. |
| الرصيد | تقفل المعاملة صف المستودع وتحسب مجموع حركات المادة بعد القفل. ترفض الكمية التي تؤدي إلى رصيد سالب قبل كتابة أي حركة أو تكلفة أو تدقيق. |
| الأثر الاقتصادي | تحسب التكلفة `الكمية × تكلفة الوحدة` بدقة منزلتين، وتكتب حركة `issue` سالبة وسجل `cost_entries` بحالة `actual/posted` وسجل `material_issues` في المعاملة نفسها. تكلفة المادة بذلك جزء من مصدر التكاليف التشغيلي الذي يستهلكه التقاط EVM القائم. |
| التدقيق | تكتب المعاملة سجل `warehouse.material_issued_to_work` يحوي المشروع والمستودع والمادة وWBS والنشاط والكمية وتكلفة الوحدة والإجمالي ومعرفي الحركة والتكلفة والرصيد قبل/بعد. |
| الواجهة | نموذج عربي/إنجليزي داخل بطاقة المستودعات القائمة. يختار مستودعًا ومادة وWBS، ويقصر النشاط على أنشطة WBS المختار، ويطلب كمية وتكلفة وحدة. لا يعرض أو يحرر تكلفة فعلية مستقلة أو معلومات رواتب. |
| الترحيل | `0045_loud_mad_thinker.sql` ينشئ `material_issues` ومفاتيحه وفهارسه فقط. روجع قبل التطبيق وطُبق على MySQL/TiDB، ثم أعاد `drizzle-kit generate` التحقق بلا فرق إضافي. |

## الدليل الحي

| الحالة | النتيجة المثبتة |
|---|---|
| مشروع عابر | رفضت محاولة صرف إلى `projectB` باستخدام مستودع/WBS من `projectA` بـ`PROJECT_OS_PROJECT_NOT_FOUND` قبل أي كتابة. |
| رصيد غير كافٍ | بعد رصيد `6`، رُفض صرف `7` بـ`PROJECT_OS_INVENTORY_INSUFFICIENT_STOCK` قبل أي أثر اقتصادي. |
| صرف مسموح | صرف `2` بتكلفة وحدة `25` من رصيد `6`، فأنتج رصيدًا لاحقًا `4` وتكلفة فعلية `50.00` وسجل صرف وحركة وتدقيقًا واحدًا لكل أثر. |
| وصول EVM | التقاط EVM التشغيلي بعد الصرف أعاد `ac=50` و`postedActualCostEntries=1`، فيثبت أن التكلفة ليست سجلاً معزولاً عن مصدر EVM القائم. |
| عزل الاختبارات | ينظف السيناريو سجل الصرف ثم التكلفة ثم الحركة ثم WBS/النشاط/المادة/المستودع والتدقيق. عُدّل دليل GRN ليقيس ثبات عدد التكلفة مقارنة بالخط الأساس، فلا يفترض غياب تكاليف مشروعة من دفعة سابقة. |
