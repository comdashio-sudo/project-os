## 1. الملخص التنفيذي

تم بناء PROJECT OS كمنصة تشغيل مشاريع مؤسسية متعددة المستأجرين بثلاثة مستويات مترابطة: **EXECUTIVE / Level 1**، و**PMO / Level 2**، و**PROJECT / Level 3**. تعمل المنصة على **MySQL/TiDB Serverless** عبر `drizzle-orm/mysql2`. يستخدم كل مسار أعمال حراسة عضوية واستحقاق وصلاحية ونطاق مستأجر/مشروع، وتكتب العمليات المحمية أثرًا تدقيقيًا ذريًا.

Dashio هي الهوية البصرية الأساسية للمنصة، بينما PROJECT OS هو الاسم الوصفي للمنتج داخل سياقات التشغيل. تفاصيل هذه التسمية في [DASHIO_BRAND_NAMING.md](./DASHIO_BRAND_NAMING.md).

| الحالة | النتيجة |
|---|---|
| بوابة الجودة الآلية | **262 اختبار وحدة/واجهة ناجحًا**، و**61** اختبار تكامل حي في MySQL/TiDB. |
| فحص الأنواع والبناء | `pnpm check` و`pnpm build` ناجحان. |
| جرد tRPC | **102 إجراءً**، صفر إجراء غير مصنف، وصفر استثناء إطار متقادم. |
| حماية سجل التدقيق | فحص المنح `approved: true` مع رفض `UPDATE` و`DELETE` لحساب التطبيق المقيد. |
| قرار Pilot | **NO-GO مشروط** فقط لحين إتمام قبول الأدوار والوصول البشري وقراءة الشاشة. |

## 3. ما نُفذ في المنصة

### 3.1 الأساس المؤسسي والأمن

تم إنشاء نموذج مؤسسي متعدد المستأجرين يشمل الشركات والعضويات والأدوار وكاتالوج الصلاحيات والنطاقات. يدعم النظام تعيين الأعضاء والأدوار والنطاقات، إنشاء الأدوار المخصصة وتحديثها، الدعوات ذات الاستخدام الواحد، وتعطيل العضويات وإعادة تفعيلها مع منع التصعيد الذاتي ومنع تعطيل آخر مالك. كل هذه المسارات محكومة بسجل تدقيق ذري.

توجد طبقة تراخيص وخطط وميزات وحدود للمقاعد والمشاريع والتخزين والاستشارات الذكية. تفرض القيود داخل المعاملات قبل كتابة الأثر، ولا تفرض حدودًا مصطنعة على مستأجر لا يحمل رخصة فعالة. كما توجد دورة حالة للرخصة وتقييم دوري لانتهائها عبر Heartbeat.

### 3.2 المستويات الإدارية الثلاثة

| المستوى | ما نُفذ |
|---|---|
| **Level 1 / EXECUTIVE** | لوحة قيادة تنفيذية، المحافظ والبرامج، التدفق النقدي، القرارات، قراءة مجمعة للميزانية والتكلفة والتنبؤ والصحة، وحراسة `executive` مع عزل المستأجر. |
| **Level 2 / PMO** | لوحات المخاطر والقضايا والإجراءات والتصعيدات، إنشاء المحافظ والبرامج وربط المشاريع، طلبات التغيير، مركز التخطيط متعدد المشاريع، ومركز «استثناءات اليوم». |
| **Level 3 / PROJECT** | سجل المشاريع، WBS والأنشطة والجدولة، الميزانيات والتكاليف والتقدم، EVM، الصحة، العقود والالتزامات وأوامر الشراء، الموارد، المطالبات، المستندات، RFI/NCR/HSE والجودة والتقارير الميدانية. |

### 3.3 الوقت والتكلفة وEVM

ينفذ النظام مؤشرات EVM القياسية بأسمائها: **PV / EV / AC / CPI / SPI / EAC / ETC / VAC**. توجد حاسبة EVM مركزية، تجميع تشغيلي من الميزانية والتكلفة والتقدم والأنشطة، لقطات EVM محمية، محرك لصحة المشروع، ومصادر استثناءات تستخدمها لوحة PMO. عولج رأس صفحة EVM ليتبع هوية Dashio، وأضيف اختبار عربي/إنجليزي ولقطات سطح المكتب والجوال.

### 3.4 العقود والموقع والجودة والمستندات

تم تنفيذ العقود والالتزامات والمطالبات والموارد والتدفق النقدي. تدعم أوامر الشراء الارتباط الاختياري بعقد أو التزام مملوك للمشروع وتسجيل الاستلام ضمن حراسة النطاق. تشمل سجلات الموقع والجودة تقارير ميدانية، وفحوص جودة، وRFI، وNCR، وHSE، مع دورات حالة محكومة وإشعارات داخلية وتدقيق.

تدعم إدارة المستندات الإصدارات والتخزين الكائني ومراجعة المستندات ضمن عزل المشروع. يفرض حد التخزين المرخص قبل الرفع أو إنشاء إصدار إضافي.

### 3.5 Excel وMaster Plan

يوفر معالج الاستيراد تحليل الملف واكتشاف الأعمدة والتعيين اليدوي والمعاينة والرفض عند الغموض والتكرار والأعمدة غير المعتمدة والملفات متعددة الأوراق. القوالب التشغيلية المنفذة هي WBS والميزانية والعقود.

**قالب العقود `contracts_v1`:** رمز العقد، العنوان، الطرف المقابل، القيمة، والعملة ذات ثلاثة أحرف. يرفض القالب العملة غير الصحيحة ورمز العقد المتكرر قبل أي كتابة، ثم ينفذ التأكيد وسجل التدقيق ذريًا.

كما تم تنفيذ Master Plan بإصدارات وكيانات مكانية وربط اختياري بـWBS والأنشطة والكيان الأب، وإعدادات عرض KPI وحفظ مرشحات وزوم وإزاحة محلية ورفع أصول معزولة للمشروع.

### 3.6 الملاحة والواجهة والوصول

توجد ملاحة مؤسسية ثنائية اللغة تحسب روابطها خادميًا وفق الحزمة والصلاحية والنطاق، وتوفر مسار الصفحة والرجوع والتقدم وقائمة مستخدم وإشعارات وبحثًا في العناصر المصرح بها فقط. لا تولد الملاحة روابط وهمية لوحدات غير محمية.

عولجت فجوة محتملة في مكوّن `FieldError`: لم يعد يملك مسارًا عامًا لعرض نص خادم خام، وأصبح يقبل محتوى صريحًا موطنًا فقط. تظل أخطاء الأعمال في الشاشات عبر `getLocalizedProjectError()`.

## 6. ما تبقى — لا يُدّعى إغلاقه

لا توجد فجوة تنفيذ برمجي مثبتة مفتوحة في السجل الحالي. الباقي هو **قبول بشري أو مزود خارجي** ولا يجوز إغلاقه باختبار آلي أو بيانات افتراضية.

| البند | حالته | لماذا لا يغلق آليًا | ما يلزم لإغلاقه |
|---|---|---|---|
| قبول الأدوار EXECUTIVE/PMO/PROJECT/منخفض الصلاحية | `HANDOFF_REQUIRED` | يتطلب جلسات OAuth حقيقية ومسارات مرئية وحسابات مستقلة. | تنفيذ `ROLE-EX-01` إلى `ROLE-LO-01` في [PILOT_ROLE_ACCEPTANCE.md](./PILOT_ROLE_ACCEPTANCE.md). |
| قارئ الشاشة والأجهزة | `HANDOFF_REQUIRED` | اختبار DOM واللقطات لا يحاكيان قارئ الشاشة أو تفضيلات المستخدم الفعلية. | تنفيذ `A11Y-01` إلى `A11Y-05` في [MANUAL_ACCESSIBILITY_ACCEPTANCE.md](./MANUAL_ACCESSIBILITY_ACCEPTANCE.md). |
| اسم Pilot ومالك البيانات الحقيقي | يحتاج مالكًا | لا يجوز افتراض عميل أو شخص مسؤول قانونيًا. | اعتماد الاسم القانوني ومالك البيانات ونطاق المشروع الأول. |
| استعادة نسخة TiDB والتخزين الكائني | يحتاج مزودًا/مسؤولًا | الاختبار الحالي منطقي داخل قاعدة اختبار، لا يثبت استعادة مزود أو مفاتيح ملفات حقيقية. | إجراء استعادة مراقبة في بيئة معزولة مع مسؤول النسخة. |
| إرسال بريد أو رسائل خارجية | `BLOCKED_BY_OWNER` | يلزم مزود وقناة وتسعير وسياسة وبيانات اعتماد معتمدة. | قرار تجاري ومزود وبيانات اعتماد؛ لا توجد حاجة له لإغلاق Pilot التقني الحالي. |

## 7. خطوات المتابعة الدقيقة

### عند بدء جلسة Pilot اليدوية

1. تأكد أن النسخة المنشورة هي `81922a56` أو نسخة أحدث موثقة.
2. جهز أربعة حسابات مستقلة داخل مستأجر Pilot واحد: EXECUTIVE وPMO وPROJECT ومنخفض الصلاحية.
3. نفذ سيناريوهات `ROLE-EX-01` إلى `ROLE-LO-01` دون SQL مباشر، وسجل الأثر المرئي ومعرّف سجل التدقيق.
4. نفذ سيناريوهات `A11Y-01` إلى `A11Y-05` على سطح مكتب وجوال وقارئ شاشة واحد على الأقل.
5. سجل النتيجة في جدولي [PILOT_ROLE_ACCEPTANCE.md](./PILOT_ROLE_ACCEPTANCE.md) و[MANUAL_ACCESSIBILITY_ACCEPTANCE.md](./MANUAL_ACCESSIBILITY_ACCEPTANCE.md)، من دون كلمات مرور أو رموز أو بيانات عميل حساسة.
6. إذا ظهر كشف بيانات عابرة للمستأجر أو كتابة محمية من دون استحقاق، يصنف العيب **حرجًا** ويظل القرار `NO-GO` حتى الإصلاح وإعادة السيناريو.
7. إذا مرت كل السيناريوهات، يعاد تشغيل بوابة الجودة ثم يحدث تقرير Pilot إلى قرار GO محدد النطاق.

### أوامر الاستئناف البرمجية

```bash
cd /home/ubuntu/project-os
pnpm test
pnpm check
pnpm build
pnpm coverage:trpc
pnpm verify:audit-grants
node scripts/run-integration-database-test.mjs
```
