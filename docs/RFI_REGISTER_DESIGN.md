# تصميم نواة سجل طلبات المعلومات

يمثل سجل RFI طلب استيضاح رسميًا مرتبطًا بمشروع واحد. يحمل المستأجر والمشروع ورقم RFI فريدًا داخل المشروع وسؤالًا وتاريخ استحقاق. لا يقبل الخادم من العميل هوية الرافع أو تاريخ التدقيق؛ يحددهما من جلسة المستخدم ووقت الخادم.

| الحالة | الانتقالات التالية | الدلالة |
|---|---|---|
| `draft` | `submitted`، `cancelled` | يُعد الطلب أو يلغى قبل إرساله |
| `submitted` | `under_review`، `answered`، `cancelled` | وصل الطلب إلى سير المراجعة |
| `under_review` | `answered`، `cancelled` | يراجع صاحب الاختصاص الطلب |
| `answered` | `closed` | قُدم الرد ويؤكد صاحب المشروع إغلاقه |
| `closed` و`cancelled` | لا شيء | حالات نهائية |

تتطلب القراءة حزمة `PROJECT` وصلاحية `project.read`، بينما يتطلب الإنشاء وانتقال الحالة `project.write` ضمن نطاق المشروع. تحفظ كل كتابة وسجل التدقيق في معاملة واحدة. لا تضم هذه الدفعة مرفقات أو مراسلات متسلسلة؛ تُربط لاحقًا بسجل المستندات دون تخزين بايتات في قاعدة البيانات.

| التغيير المخطط | الأثر | التحقق | الاسترجاع |
|---|---|---|---|
| إنشاء جدول `rfis` | سجل معزول بالمستأجر والمشروع ورقم فريد | فحص الجدول والفهرس | حذف قبل بيانات إنتاجية فقط |
| إنشاء RFI | سجل وسجل تدقيق في معاملة واحدة | اختبار السماح وعدّ الكتابات | لا يكتب شيء عند رفض التفويض |
| انتقال RFI | تحديث الحالة وسجل تدقيق ذري | اختبار الانتقال القانوني وغير القانوني | لا تغيير عند رفض الانتقال |
