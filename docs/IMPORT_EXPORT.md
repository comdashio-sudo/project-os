# محرك الاستيراد والتصدير الموحد

## نطاق النواة

يقدم PROJECT OS خدمة بيانات مشتركة بدل منطق رفع مكرر داخل الوحدات. تدعم النواة قوالب **WBS** و**الميزانية** و**العقود** المحددة صراحةً؛ ولا تقبل «ملف Excel عامًا» لأي قسم. تقبل خدمة التحليل ملفات `XLSX` و`CSV` فقط، وتحفظ الملف الأصلي في التخزين الكائني مع مفتاحه وبصمته في السجل؛ لا تخزن بايتات الملف في قاعدة البيانات.

| مرحلة | الضابط الخادمي |
|---|---|
| اختيار القالب والمشروع | استحقاق PROJECT وصلاحية القراءة أو الكتابة ونطاق المشروع. |
| التحليل والتعيين | لا يعيّن الحقول منخفضة الثقة تلقائيًا؛ يطبع العناوين العربية والإنجليزية ويعيد تعيين الحقول فقط عند تطابق معروف. |
| التحقق والمعاينة | يتحقق من نوع الملف والحقول الإلزامية والقيم الرقمية غير السالبة لكل صف؛ لا تعرض خطوة التأكيد عند وجود خطأ. |
| التأكيد والاستيراد | يعيد تنزيل الملف الأصلي بمفتاح التخزين، ويتحقق من بصمة SHA-256 والنطاق وقابلية التأكيد والتكرار، ثم يكتب سجلات WBS أو الميزانية أو العقود وتحديث السجل ونتيجة كل صف وسجل تدقيق واحد داخل معاملة. |
| التصدير | يجلب المصدر المحمي نفسه ثم يصدّر فقط الأعمدة والصفوف المصرح بها. |

## سجل التشغيل

يحفظ سجل الاستيراد معرفه والمستأجر والمشروع عند وجوده والوحدة والقالب واسم الملف والمفتاح والبصمة والحالة وسياسة التكرار والعدادات والنتائج المختصرة والمنشئ والمدة. تحفظ أخطاء التحقق في `data_import_errors`، وتحفظ نتيجة كل صف صحيح في `data_import_row_results` برقم الصف ومفتاح العمل والإجراء الفعلي ومعرّف السجل عند وجوده. لا تنفذ قيمة ملف مباشرة كمعرّف مشروع أو WBS دون حلها ضمن المستأجر والمشروع.

يقبل التأكيد السجل ذي الحالة `validated` فقط، ويرفض التكرار داخل الملف في جميع السياسات قبل بداية المعاملة. أما التكرار الموجود مسبقًا ضمن المشروع فتطبّق عليه السياسة المحفوظة مع سجل التحليل: `fail_on_duplicate` أو `create_only` يوقفان العملية، و`skip_duplicates` ينشئ السجلات الجديدة ويتجاوز الموجودة، و`update_existing` يحدث الموجودة فقط ويتجاوز غير الموجودة، و`upsert` يحدث الموجودة وينشئ الجديدة. بعد النجاح تتحول الحالة إلى `completed` مع عدادات الإنشاء والتحديث والتجاوز ووقتَي البداية والإكمال. تعرض واجهة Level 3 سياسة السجل وملخص عداداته ونتائج صفوفه المحفوظة بالعربية والإنجليزية، ولا تتجاوز آلية التأكيد أي ملف أو صف أو مشروع غير مصرح به.

## قالب العقود المعتمد — `contracts_v1`

قالب العقود هو قالب Pilot الخادمي الأول. يتطلب خمسة أعمدة فقط: **رمز العقد / Contract Code**، و**اسم العقد / Contract Title**، و**الطرف المتعاقد / Counterparty**، و**قيمة العقد / Contract Value**، و**العملة / Currency**. يقبل النظام مرادفات العناوين العربية والإنجليزية المحددة في القالب، ويعرضها في المعاينة، لكنه يرفض أي عمود إضافي غير معتمد وأي ملف متعدد الأوراق أو أي رمز عقد مكرر داخل الملف.

يجب أن تكون قيمة العقد رقمًا غير سالب، وأن تكون العملة رمز ISO مكوّنًا من ثلاثة أحرف مثل `SAR` أو `USD`؛ ويحوّل رمز العملة الصحيح إلى أحرف كبيرة. يحفظ تأكيد الملف السليم العقد أو يحدثه حسب سياسة التكرار، ويكتب نتائج الصفوف في `data_import_row_results`، كما يسجل الحدثين `data_import_uploaded` و`data_import_completed` المستقلين ضمن `audit_logs`. يرفض النظام المشروع العابر للمستأجر قبل التخزين أو إنشاء سجل الاستيراد أو سجل التدقيق.

## التصدير المنفذ

يدعم المسار `dataImports.export` وحدات **WBS** و**الميزانية** و**الأنشطة** بصيغتي `XLSX` و`CSV`. يفرض عضوية المستأجر واستحقاق `PROJECT` وصلاحية `project.read` ونطاق المشروع قبل قراءة أي سجل. ينتقي الاستعلام أعمدة القالب فقط ولا يعيد مفاتيح المستأجر أو معرفات العلاقات أو حقول التدقيق. ينشئ المولد رؤوسًا عربية أو إنجليزية وفق لغة الواجهة، ويعيد البيانات مشفرة Base64 للتنزيل المباشر في المتصفح ثم يسجل حدث `data_export_generated` في معاملة منفصلة.

## حدود الدفعة الأولى

لا تنفذ الدفعة الحالية معالجة دفقية قابلة للاستئناف للملفات الضخمة أو تراجعًا عامًا للكتابات التجارية بعد التأكيد. تمثل نتائج الصفوف دليل أثر تشغيلي، لا آلية عكس تلقائي. تبقى قيود الحزمة وعدد الاستيراد/التصدير قابلة للضبط في الاستحقاقات ولا تُثبت في الواجهة.
