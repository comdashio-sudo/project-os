## النتيجة

الملف المرفق هو مرجع منهجي وهندسي، وليس مواصفة ميزة جديدة قابلة للتحويل حرفيًا إلى أمر تنفيذي واحد. اعتمدت المبادئ الملائمة في `ENGINEERING_REFERENCE.md`، وراجعت صلتها بالمنصة الحالية وبأحدث دفعة انتقال حالة العضوية. لا يُنقل وصف المصدر التقني الوارد في الملف — Next.js أو Supabase/PostgreSQL أو Vercel — إلى PROJECT OS، لأن البنية الفعلية المعتمدة هنا هي React وExpress وtRPC وDrizzle مع MySQL/TiDB، وفق قرار عزل مستقل موثق.

| جزء المرجع | القرار داخل PROJECT OS | الدليل أو الأثر |
|---|---|---|
| الدليل لا الادعاء | مطبق | `TEST_EVIDENCE_MATRIX.md` يسجل أوامر قابلة لإعادة التشغيل ومخرجاتها وحدودها. |
| تصنيف موضع الفرض | مطبق | `ENGINEERING_REFERENCE.md` يميز قاعدة البيانات والخادم والواجهة، وتبقى الواجهة غير طبقة فرض. |
| عزل المستأجر والمسارات الشقيقة | مطبق | مشغل MySQL/TiDB يثبت الرفض العابر والسماح والتدقيق للتدفقات التشغيلية، ومنها انتقال العضوية. |

## التحقق الخاص بالدفعة الحالية

أنشأ اختبار التكامل الحي دور إدارة مؤقتًا، ودعا مستخدم اختبار ثم قبل الدعوة للحصول على عضوية قابلة للتجربة. يثبت الاختبار النتائج التالية في قاعدة `project_os_integration_test` ويزيل صفوفه المؤقتة بترتيب المفاتيح الأجنبية.

| التجربة | النتيجة المثبتة | الأثر المتوقع |
|---|---|---|
| العضو يحاول تعطيل عضويته | رفض `PROJECT_OS_SELF_PRIVILEGE_CHANGE_FORBIDDEN` | لا انتقال ذاتي ولا سجل تدقيق انتقال. |
| المدير يطلب مستأجرًا لا ينتمي إليه | رفض `PROJECT_OS_TENANT_ACCESS_DENIED` | لا يفحص عضوية الهدف أو يكتب سجلًا في المستأجر الآخر. |
| المدير يعطل عضوية في مستأجره | نجاح إلى `suspended` | صف عضوية واحد بالحالة الصحيحة. |
| المدير يعيد نفس التعطيل | رفض `PROJECT_OS_MEMBERSHIP_STATUS_TRANSITION_INVALID` | لا انتقال مكرر. |
| المدير يعيد تفعيل العضوية | نجاح إلى `active` | سجلا `tenant.membership_status_changed` للتعطيل والإعادة. |

## ما لم ينفذ ولماذا

| بند في المرجع | الحالة | السبب وخطوة الإغلاق |
|---|---|---|
| مشغلات قاعدة البيانات لحصانة `audit_logs` | غير ممكن في TiDB Serverless الحالي | لا يدعم TiDB Serverless المشغلات؛ يلزم MySQL/InnoDB أو حساب تشغيل منفصل وضوابط وصول بديلة. |
| RLS وسياسات PostgreSQL | غير مطبق عمدًا | ليست من قدرات MySQL/TiDB ولا من قاعدة بيانات PROJECT OS المعتمدة؛ يستبدلها التحقق الخادمي والنطاقات والمفاتيح الحالية. |
| إرسال بريد أو رموز عبر مزود خارجي | غير مطبق | يتطلب قناة بريد وبيانات اعتماد وسياسة تسليم خارجية؛ لا يفتح أو ينشئ اتصالًا خارجيًا بلا هذه المتطلبات. |
| فحص قارئ شاشة يدوي شامل | غير متحقق بالكامل | تغطي اختبارات DOM مسارات تركيز وتسميات محددة، لكن يلزم مراجعة يدوية تخصصية للحسابات والمسارات كافة. |

## قرار البند

يُغلق بند مراجعة الملف المرفق لأن كل أمر مناسب وآمن جرى ربطه بآلية PROJECT OS أو بدليل قائم، ولأن الأوامر غير القابلة للتطبيق سُجل سببها ومسار إغلاقها بدل تنفيذ بديل غير متوافق. لا يحوّل هذا القرار حدود TiDB أو الاعتماديات الخارجية أو الوصول الشامل إلى عناصر مقبولة نهائيًا.
