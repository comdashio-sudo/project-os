# سجل التقارير الميدانية

## النطاق

يوفر سجل التقارير الميدانية في **Level 3** أثرًا تشغيليًا لتقرير يومي أو تفتيشي أو تقرير تقدم ضمن مشروع واحد. يتضمن السجل رقم التقرير، النوع، تاريخ التقرير، الوردية، عدد العاملين، وصف الطقس الاختياري، والملخص الميداني. لا يخزن هذا السجل مرفقات أو بايتات ملفات؛ تظل المرفقات ضمن سجل المستندات المحكوم.

## الحراسة الخادمية

| العملية | الحراسة المطبقة |
|---|---|
| القراءة | عضوية المستأجر، حزمة PROJECT، صلاحية `project.read`، وملكية المشروع. |
| الإنشاء | عضوية المستأجر، حزمة PROJECT، صلاحية `project.write`، وملكية المشروع، مع عدد عاملين صحيح بين 0 و100000. |
| انتقال الحالة | الحراسة نفسها للكتابة، ثم اختيار التقرير بالنطاق الثلاثي: المعرّف والمستأجر والمشروع. |
| التاريخ التشغيلي | تنشئ كل كتابة أو انتقال سجل تدقيق داخل المعاملة نفسها. |

## دورة الحالة

```text
draft → submitted → reviewed → approved
                    └→ rejected → draft
```

لا توجد انتقالات من `approved`، ولا يسمح الخادم بتجاوز الانتقال المحدد حتى لو تغيرت الواجهة.

## التحقق المثبت

يثبت تكامل MySQL/TiDB رفض إنشاء أو انتقال تقرير لمشروع مستأجر آخر قبل الكتابة، ثم يثبت الإنشاء والانتقالين `draft → submitted → reviewed` وثلاثة سجلات تدقيق مرتبطة بالتقرير. تثبت اختبارات الواجهة إدخال تقرير تفتيشي، وتمرير المستأجر والمشروع والنوع والوردية وعدد العاملين، وإتاحة الانتقال التالي فقط، والتعريب العربي للعنوان والحالة وزر الانتقال.

## الحد الحالي

لا يربط السجل التقارير تلقائيًا بـWBS أو بالمخاطر أو بالمستندات، ولا يرسل إشعارًا خارجيًا عند الانتقال. تمثل هذه روابط ووظائف لاحقة تتطلب نقطة تقارب وحراسة مستقلة.
