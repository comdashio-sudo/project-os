# سجل فحوصات الجودة

## النطاق

يوثق سجل فحوصات الجودة في **Level 3** نقطة توقف أو مشاهدة أو مراقبة أو اختبار ضمن مشروع واحد. يتضمن السجل رقمًا فريدًا داخل المشروع، ونوع الفحص وتاريخه ونتيجته وملخصه وحالة دورة العمل. لا ينشئ هذا السجل تلقائيًا NCR أو ربط WBS أو مرفقًا؛ تلك تكاملات مستقلة لاحقة.

## الحراسة ودورة الحالة

| العملية | الفرض الخادمي |
|---|---|
| القراءة | عضوية المستأجر، حزمة PROJECT، صلاحية `project.read`، وملكية المشروع. |
| الإنشاء | عضوية المستأجر، حزمة PROJECT، صلاحية `project.write`، وملكية المشروع. |
| الانتقال | اختيار الفحص وفق المعرّف والمستأجر والمشروع، ثم خريطة حالة ثابتة. |
| التدقيق | كل إنشاء أو انتقال يكتب سجل تدقيق داخل المعاملة نفسها. |

```text
draft → submitted → accepted
                └→ rejected → draft
```

## التحقق المثبت

يثبت تكامل MySQL/TiDB رفض إنشاء فحص أو انتقاله في مشروع مستأجر آخر قبل الكتابة، ثم إنشاء فحص اختبار بنتيجة مشروطة وانتقاله `draft → submitted → accepted` مع ثلاثة سجلات تدقيق قابلة للاستعلام. تثبت اختبارات DOM إدخال نوع اختبار ونتيجة مشروطة، وتمرير نطاق المشروع، وإتاحة الانتقال التالي فقط، وتعريب عنوان السجل وزر الانتقال.

## الحد الحالي

تمثل النتيجة قيمة مدخلة ومراجعة تشغيلية؛ لا تحول النتيجة `fail` تلقائيًا إلى NCR ولا ترسل قناة خارجية. يتطلب ذلك قرار ربط وسير عمل منفصلين ومحكومين بالنطاق.
