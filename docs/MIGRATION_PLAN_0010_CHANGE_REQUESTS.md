# خطة ترحيل 0010 — سجل طلبات التغيير

## الهدف والنطاق

تنشئ هذه الترحيل جدول `change_requests` لسجل طلبات تغيير مستقل للمستأجر والمشروع. يتيح السجل تسجيل أثر زمني ومالي صريح، مع دورة حالة خادمية لاحقة: `draft → submitted → under_review → approved/rejected`، والإلغاء من الحالات غير النهائية فقط.

> لا تنفذ هذه الترحيل أي تعديل تلقائي للميزانية أو البرنامج الزمني أو العقد؛ طلب التغيير سجل حوكمة منفصل حتى يُعتمد أثره بواسطة إجراء تشغيلي مستقل وموثق.

| عنصر | الأثر المتوقع |
|---|---|
| العزل | `tenantId` و`projectId` مفاتيح أجنبية إلزامية، وفهرس نطاق يجمع المستأجر والمشروع والحالة. |
| الفرادة | رقم طلب التغيير فريد داخل المشروع فقط، فلا يكشف سجل مستأجر أو مشروع آخر. |
| الأثر | يحتفظ السجل بأيام الأثر الزمني وقيمة الأثر المالي كما أُعلنت عند الطلب، دون تطبيقهما تلقائيًا. |
| التدقيق | لا تُنشأ أعمدة تدقيق قابلة للعميل؛ تكتب خدمات الخادم سجلات `audit_logs` مع الإنشاء والانتقال. |

## SQL المتوقع والتحقق

ينتج `pnpm drizzle-kit generate` جدول `change_requests` وفهارس نطاقه. بعد مراجعة SQL، يطبق عبر تنفيذ قاعدة البيانات ثم يتحقق الاستعلام التالي من وجود الجدول وفهرس نطاقه:

```sql
SELECT table_name
FROM information_schema.tables
WHERE table_schema = DATABASE() AND table_name = 'change_requests';

SHOW INDEX FROM change_requests;
```

## الاسترجاع

قبل أي بيانات أعمال في الجدول، يكون الاسترجاع هو حذف فهارسه ثم الجدول فقط. بعد وجود بيانات، لا يحذف الجدول في بيئة تشغيلية؛ يعاد ترحيل علاجي يضيف أو يعدل القيد المقصود، مع تصدير السجلات المتأثرة وموافقة تشغيلية.
