# استراتيجية الاختبار

لا تُعتمد ميزة إلا بعد اختبارات وحدة وتكامل وانحدار ملائمة للمخاطر. يتضمن مسار الفحص `typecheck` و`test` و`build` ثم اختبارات صلاحية وعزل وواجهة للسيناريوهات الحرجة.

| المستوى | أمثلة |
|---|---|
| وحدة | معادلات PV وEV وAC وCPI وSPI وEAC وETC وVAC وحالات القسمة على صفر. |
| تكامل | إنشاء مشروع وربطه بميزانية وتقدم وتكلفة ثم إنشاء لقطة EVM. |
| صلاحيات | دور PMO، مدير المشروع، والعضو العادي مع فحص مواردهم المسموح بها. |
| عزل | شركتان مستقلتان لا تستطيعان رؤية بيانات بعضهما. |
| واجهة | حالات التحميل والفراغ والخطأ والمنع والتنقل الأساسي. |

## أدلة مطلوبة وفق المرجع الهندسي

| القاعدة | الدليل المطلوب | الحالة |
|---|---|---|
| لا نجاح صامت للكتابة | تحقق من الصف العائد أو إعادة جلب المصدر قبل تحديث الواجهة. | مفتوح لكل إجراءات الكتابة الجديدة. |
| عزل المستأجر | طلب مورد مستأجر آخر بواسطة معرفه المباشر؛ النتيجة المتوقعة رفض بلا كشف بيانات. | مغطى جزئيًا بعقد API مموه يتحقق من الرفض قبل تحميل المورد أو بدء معاملة كتابة؛ اختبار تكامل فعلي بقاعدة اختبارية ما زال مطلوبًا. |
| الاستحقاق | لكل إجراء تشغيلي: اختبار حزمة تمنعه واختبار حزمة تسمح به. | مغطى جزئيًا لمسارات الحجب: لقطة EVM وWBS والتكلفة والتقدم والميزانية ترفض عند غياب استحقاق PROJECT؛ يبقى اختبار السماح مع بيانات حقيقية واختبار قاعدة البيانات المستقلة مفتوحين. |
| المسارات الشرعية | بعد كل تضييق حماية، اختبار المسار الشرعي المقابل بالمدخلات الصحيحة. | مطلوب لكل دفعة أمنية. |
| رسائل الرفض | تعرض الواجهة رسالة ثنائية اللغة قابلة للتصرف بدل خطأ قاعدة بيانات خام. | مغطى: طبقة API تضيف رمزًا ورسالتين عربيتين/إنجليزيتين، وتستخدم صفحات مساحة العمل وسجل المشاريع وحاسبة EVM الرسالة بحسب اللغة الحالية؛ لم يبقَ عرض مباشر لـ `error.message` في هذه الصفحات. |

## آخر نتيجة تحقق

نجحت حزمة الاختبارات الحالية في **28 اختبارًا** عبر ستة ملفات، وتشمل تسجيل الخروج، وحدود الحزمة التجارية، وعزل المستأجر، ونطاق الدور، وحراسة نطاق WBS في المسارات الشقيقة، وحجب جميع إجراءات الإدخال التشغيلية عند غياب استحقاق PROJECT، وجميع طرق EVM وحالات القسمة على صفر والمدخلات غير الصحيحة، وقواعد صحة المشروع والاستثناءات. تعتمد اختبارات العزل والاستحقاق التشغيلية الحالية على محاكاة طبقة قاعدة البيانات، ولذلك لا تمثل بديلًا لاختبار تكامل قاعدة بيانات مستقل. كما نجح فحص TypeScript والبناء الإنتاجي.

تمت مراجعة واجهتي مساحة العمل وحاسبة EVM بصريًا على سطح المكتب والهاتف؛ تحافظ الواجهتان على ترتيب قابل للاستخدام للنماذج والمحتوى في العرض الضيق.

تمت مراجعة مسارات الصفحة الرئيسية وحاسبة EVM بعد إضافة تبديل اللغة؛ يظهر زر الانتقال إلى العربية في رؤوس الواجهات، ويمرر فحص TypeScript والبناء الإنتاجي بعد إدخال طبقة اللغة.

تم التحقق بصريًا من العرض العربي الصريح عبر `?lang=ar` في الصفحة الرئيسية وحاسبة EVM وصفحة 404. تظهر النصوص العربية وترتيب RTL وزر العودة إلى الإنجليزية بصورة صحيحة، ثم تمت معالجة انزياح العرض الأفقي الذي ظهر في المراجعة الأولى بإلزام حاويات التطبيق بعرض الصفحة ومنع التجاوز الأفقي.

## قبل كل دفع: التشغيل الكامل محليًا (أمر المالك 2026-10-27)

دقائق GitHub Actions نفدت مرة. فالطلب في CI لا يشغّل إلا الفحوص الخفيفة (مهمة واحدة، نحو دقيقتين)، والاختبارات الكاملة تُشغَّل محليًا قبل الدفع:

```bash
# PostgreSQL محلي، DATABASE_URL = مشرف على الخادم المحلي (لا قاعدة إنتاج أبدًا)
pnpm verify:local
```

يشغّل: `pnpm check` ← توافق الترحيلات ← فحص الأسرار ← `pnpm build` ← `pnpm test` ← مجموعة قاعدة البيانات (`scripts/run-integration-database-test.mjs`، بحساب التطبيق المقيَّد).
والمهام الثقيلة في CI (البناء والاختبارات، مجموعة القاعدة، لقطات اللغات الثلاث، الرحلات الثلاث) تعمل **مرة واحدة على `main` بعد الدمج**، ويلغي الدفع الأحدث على الفرع نفسه التشغيل الأقدم، والإطلاق الآلي (`migrate-production.yml`) لا يبدأ إلا بعد نجاحها.
