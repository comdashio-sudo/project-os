# تنفيذ المرحلة A — نموذج وحساب PMC

**التاريخ:** 8 أكتوبر 2026
**النطاق:** المرحلة A فقط من `docs/WORK_ORDER_PMC.md`
**المحرك:** MySQL/TiDB Serverless
**بيانات حقيقية أو بيانات مستفيدين:** لم تُستخدم ولم تُنشأ.

## ما أُنجز

- أضيفت جداول PMC الاثنا عشر، وكل جدول يحمل `tenantId` و`projectId`:
  - Zone / Block / Unit
  - Activity Group / Stage / Definition
  - Unit Activity Progress / History
  - Verification Status
  - Inspection Request / Steps
  - Baseline
- أضيفت المفاتيح الأجنبية للمراجع المؤسسية والمشروع والوحدة والنشاط والمستخدم.
- أضيفت فهارس `tenant/project` للوصول المحكوم.
- أضيف ترحيل Drizzle: `drizzle/0052_pmc_phase_a.sql`.
- أضيف محرك الحساب النقي في `server/domain/pmc.ts`.
- أضيف فحص بنيوي قابل لإعادة التشغيل في `scripts/verify-pmc-schema.mjs` وأمر:
  - `pnpm verify:pmc-schema`

## دليل القواعد السبع

الاختبار `server/domain/pmc.test.ts` يثبت 7/7:

1. تقدم الوحدة = مجموع وزن النشاط × معامل الحالة؛ الافتراضي أن `COMPLETE` فقط يضيف تقدمًا، والمعاملات قابلة للتهيئة.
2. تقدم المشروع متوسط مرجح بوزن الوحدة، مع تساوٍ افتراضي عند غياب الوزن.
3. نسبة إنجاز النشاط ترفض `completed > included` ولا تسمح بنتيجة تتجاوز 100%.
4. أوزان نموذج النشاط تُرفض إن لم تساوِ 100% بالضبط أو تضمنت تكرارًا.
5. السجل يُرفض عند غياب Group أو Stage أو Activity.
6. نطاقات التقارير تُرتب إلى أول وآخر رقم وحدة.
7. EV يُحسب من تقدم عنصر WBS وميزانيته.

## ملاحظة تطبيق قاعدة البيانات

المحاولة الأولى لتطبيق SQL نفذت إنشاء الجداول ثم توقفت عند حد طول اسم قيد TiDB، فبقيت جداول PMC بلا بيانات. عولجت أسماء القيود الطويلة بأسماء قصيرة، استُكملت القيود والفهارس، ثم صُحح `pmc_blocks.createdAt` ليطابق Drizzle. لم تُحذف بيانات حقيقية؛ استخدم اختبار التكامل صفوفًا تركيبية مؤقتة ونظفها بعد الاختبار، ولم يستخدم أي مستفيدين.

## ما لم يُنفذ في المرحلة A

- لا استيراد Excel/CSV أو XER.
- لا شاشات أو تقارير أو مخطط موقع أو منحنى S.
- لا بيانات مستفيدين ولا أسماء مهندسين/استشاريين حقيقيين.
- لا ربط Google Sheets.
- لا إغلاق للمراحل B أو C أو D.
- أضيفت قراءة خادمية محكومة واختبار سلوك حي للعزل؛ لا تزال عمليات الكتابة والاستيراد والشاشات خارج المرحلة A.

## دليل اختبار العزل

أضيفت قراءة `pmc.summary` محكومة بحارس المستأجر والمشروع. الاختبار الحي يزرع بيانات تركيبية منفصلة في المستأجرين عبر الجداول الاثني عشر، ثم يثبت أن المستأجر A يرى 12/12 صفًا له فقط، وأن طلب `tenantA + projectB` يُرفض قبل القراءة برسالة `PROJECT_OS_PROJECT_NOT_FOUND`. لا توجد بيانات مستفيدين أو أسماء حقيقية.

**الحكم:** المرحلة A مغلقة بالأدلة المحددة أعلاه. المرحلة B لم تبدأ.
