# المهام والأعضاء — تقرير (Q-45 ج، P2-09)

الحالة على `main` في 2026-11-18. **توضيح وتنقل؛ لا نظام جديد دون إثبات النقص.**

## 1. ما يوجد

| الموضوع | أين | ما يعمل |
|---|---|---|
| المهام (الإجراءات) | جدول `actions` (العنوان، الوصف، الأولوية، **المالك** `ownerMembershipId`، الاستحقاق، دليل الإنجاز، التصعيد، الحالة)؛ `pmo.createAction` و`pmo.transitionActionEscalation` | التسجيل والتصعيد، والمتأخرة في لوحة PMO |
| الربط بين السجلات | `control_record_links` (خطر/قضية/إجراء/قرار) | يعمل |
| الحسابات والدعوات | `users`، `membership_invitations`؛ الدعوة بالبريد (Q-12) | يعمل |
| العضوية والأدوار | `memberships`، `membership_roles` بنطاق شركة/محفظة/برنامج/مشروع؛ إدارة الشركة | يعمل، والصلاحية لكل تعيين (D-18، D-19) |
| فريق المشروع | `/projects/:t/:p/team` (Q-12) | الأعضاء والدعوات المنتظرة ودعوة بدور |
| التفعيل والإيقاف | `memberships.status` (invited · active · suspended · revoked) في إدارة الشركة | يعمل، ولا يُعطَّل آخر مالك |

## 2. النقص المثبت

| النقص | الدليل | المقترح |
|---|---|---|
| لا قائمة «مهامي» للمالك المسنَد إليه | لا شاشة تصفّي `actions` بـ`ownerMembershipId` للمستخدم الحالي | صفحة «مهامي» تقرأ ما يملكه الشخص عبر مشاريعه |
| التوزيع حسب الإدارة | لا مفهوم «إدارة/قسم» في `memberships` أو `roles` | **لا يُضاف قبل قرار**: التوزيع اليوم حسب المشروع والدور |
| نقل حالة المهمة (مفتوحة ← منجزة) | التصعيد وحده له إجراء؛ الحالة تُقرأ ولا تُنقل من الواجهة إلا عبر التصعيد | إجراء «إنجاز المهمة» للمالك بدليل اختياري |
| أين يجد المدير الأعضاء | إدارة الشركة (كل الأعضاء) وفريق المشروع (أعضاء المشروع) في مكانين | رابط متبادل بين الصفحتين، ضمن Q-36 (التنقل) |

## 3. القرار المطلوب

1. صفحة «مهامي» وإجراء «إنجاز المهمة» (لا جدول جديد).
2. هل يُضاف مفهوم «الإدارة/القسم»؟ التوصية: لا الآن.
