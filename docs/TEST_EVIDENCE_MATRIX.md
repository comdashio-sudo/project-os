# مصفوفة أدلة الاختبار والتكامل — PROJECT OS

**تاريخ المراجعة:** 20 أغسطس 2026.  
**قاعدة الحكم:** لا تعد نتيجة البناء وحدها دليل قبول؛ يجب أن يثبت المسار المصرح، وحالة الرفض ذات الصلة بالنطاق أو الاستحقاق، والأثر التدقيقي للكتابات التشغيلية.

> هذه المصفوفة تسجل الدليل القابل لإعادة التشغيل كما هو، ولا تحول اتساع التغطية إلى ادعاء بأن كل مسار في الشفرة قد مُثّل بحالة مستقلة.

## جرد إجراءات tRPC

تشغل الأداة القراءة فقط `node --import tsx scripts/inventory-trpc-procedures.mjs`. وفي المراجعة الحالية سجلت **97 إجراء tRPC**، ووجدت **92 إجراءً** له مرجع مباشر في `server/integration.database.test.ts`. لا يساوي المرجع المباشر عدد الحالات، لأن بعض الحالات تغطي أكثر من إجراء ومجموعة من الحراس، لكنه معيار جرد مفيد لمنع الخلط بين اتساع المجال وعدد الإجراءات الفردية.

يفرض الأمر `pnpm coverage:trpc` الآن هذا الجرد في وضع تحقق: يفشل إذا ظهر إجراء بلا مرجع تكاملي مباشر ولا استثناء، أو إذا لم يعد استثناء الإطار المدرج موجودًا في الموجّه. سجل آخر تشغيل **صفر إجراءات غير مصنفة وصفر استثناءات قديمة**.

| فئة بلا مرجع تكامل مباشر حاليًا | العدد | أمثلة | قرار المصفوفة |
|---|---:|---|---|
| إطار الجلسة أو النظام | 5 | `access.check` و`auth.me` و`auth.logout` و`system.health` و`system.notifyOwner` | تعالج عبر اختبارات الإطار أو تشغيل النظام؛ لا تستدعي قاعدة التكامل إشعار المالك الحقيقي ولا تعد دليل عزل مشروع مستقل. |
| قراءات غلاف تشغيلية | 0 | لا توجد قراءة تشغيلية بلا مرجع مباشر في الجرد الحالي. | تحافظ الإضافات المستقبلية على دليل نطاق مصرح ورفض عابر قبل الإغلاق. |
| كتابات أو انتقالات ذات أثر أمني/تشغيلي | 0 | لا توجد كتابة أو انتقالات تشغيلية عالية الأثر بلا مرجع مباشر في الجرد الحالي. | تحافظ الإضافات المستقبلية على شرط حارس الرفض والسماح والتدقيق قبل الإغلاق. |

تغلق نتيجة الجرد فئتي الكتابات والانتقالات وقراءات الغلاف التشغيلية الحالية. تبقى فقط إجراءات إطار أو نظام موثقة منفصلة، ولا تغلق بنود اختبارات الواجهة والأمان منخفضة الصلاحية.

## الحدود الصريحة

| الحد | لماذا لا يعد مغلقًا | مسار الإغلاق |
|---|---|---|
| حصانة `audit_logs` على مستوى قاعدة البيانات | لا يدعم TiDB Serverless المشغلات اللازمة لمنع `UPDATE` و`DELETE`. | تشغيل MySQL/InnoDB أو حساب تشغيل محدود وطبقة قيود بديلة. |
| التعداد الحرفي لكل إجراء مرخص | تغطي 50 حالة حية المجالات والإجراءات الحرجة، وتستثني خمسة إجراءات إطار محددة بالأسماء في هذه المصفوفة. | فرض قائمة إجراءات مرجعية آلية وربط كل إجراء جديد بحالة رفض وسماح أو باستثناء إطار موثق قبل إضافته. |
| حذف كائنات تخزين الاختبار | واجهة التخزين المدمجة لا تعرض حذفًا للكائن؛ ينظف الاختبار صفوف النسخة والمستند وسجلات التدقيق فقط. | تبقى مفاتيح اختبار فريدة غير مرجعية وغير قابلة للوصول عبر التطبيق؛ توثق هذه الحدود بدل ادعاء حذف مادي. |
| اختبار النصيحة المصرح بها طرفيًا | فحص رفض المستشار الذكي يمنع مشروعًا عابرًا قبل النموذج؛ لا يشغل طلب نموذج مصرح في كل انحدار لتكلفته الخارجية. | تشغيل اختبار طرفي مخصص عند توفر ميزانية نموذج وسياسة تشغيله. |
| الوصول الشامل | توجد أدلة DOM للتركيز والتسميات في مسارين، لكنها لا تغطي قارئات الشاشة أو التنقل اليدوي عبر كل مسار وحالة أو جميع حسابات الصلاحيات المنزوعة. | توسيع الاختبارات الآلية وجلسات حسابات مقيدة ومراجعة قارئ شاشة لكل مستوى. |

## قرار التسوية

تثبت الحزمة الحالية اختبارات الوحدة والواجهة والتكامل والعزل والاستحقاق للعمليات الحرجة المنفذة، مع نتائج قابلة لإعادة التشغيل ومخزن تكامل مستقل. تغطي جميع إجراءات الأعمال الحالية بمرجع مباشر أو باختبار أعلى، وتستثني إجراءات الإطار الخمسة المسماة أعلاه. توسعت أدلة الوصول المنخفض الصلاحية ولوحة المفاتيح، بينما تظل مراجعة قارئات الشاشة، والتنقل اليدوي الشامل، وتكلفة اختبار النصيحة، وقيد TiDB ضمن معايير القبول ولا تُخفى بتحديث إداري.
