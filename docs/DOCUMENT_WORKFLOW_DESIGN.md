# تصميم انتقالات مراجعة المستندات

تستعمل نواة سير العمل حالة سجل المستند القائمة ولا تقبل من العميل تاريخًا أو منفذًا للمراجعة. يتطلب كل انتقال حزمة `PROJECT` وصلاحية `project.write` ونطاق المشروع، ويتحقق الخادم من أن المستند والمشروع والمستأجر متطابقون قبل أي تحديث أو سجل تدقيق.

| الحالة الحالية | الحالات التالية المسموحة | الدلالة التشغيلية |
|---|---|---|
| `draft` | `for_review`، `archived` | مستند جديد جاهز لبدء المراجعة أو إلغائه منطقيًا |
| `for_review` | `draft`، `approved` | إعادة صياغة أو اعتماد |
| `approved` | `superseded`، `archived` | استبدال بإصدار أو إيقاف منطقي |
| `superseded` | `archived` | حفظ السجل التاريخي ثم أرشفته |
| `archived` | لا شيء | حالة نهائية لا يعاد فتحها في هذه الدفعة |

يكتب التحديث وسجل التدقيق في معاملة واحدة. ترفض الخدمة الانتقال إلى الحالة نفسها أو أي قفزة ليست في الخريطة. لا تغير هذه الدفعة رقم الإصدار أو ملف التخزين؛ يظل رفع إصدار جديد مسارًا مستقلاً، ولا يرفع الحالة تلقائيًا. يجب إثبات رفض مستند خارج المشروع ورفض انتقال غير مسموح والسماح الذري، وأن تعرض الواجهة الخيارات التالية فقط مع رسالة موطّنة.
