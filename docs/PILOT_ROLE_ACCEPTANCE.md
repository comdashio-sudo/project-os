# قبول أدوار Pilot المنظم

## الغرض والنطاق

يوثق هذا السجل الدليل الآلي القابل لإعادة التشغيل لقبول الأدوار في بيئة MySQL/TiDB المعزولة. لا يمثل هذا السجل بديلًا عن جلسة قبول يدوية لدى مالك الـPilot؛ بل يثبت أن الحراس الخادمية والأثر التشغيلي وسجل التدقيق تؤدي المطلوب تحت هويات أدوار مستقلة.

> معيار القبول هو **الرفض بلا أثر** عند غياب الصلاحية، ثم **السماح بأثر أعمال حقيقي وسجل تدقيق** عند وجود الصلاحية؛ ولا يكفي نجاح استجابة API شكليًا.

| الدور التجريبي | الصلاحيات المستخدمة | مساحة العمل | أثر السماح المثبت | رفض منخفض الصلاحية |
|---|---|---|---|---|
| `EXECUTIVE` | `executive.read` و`tenant.manage` | المؤشرات والقرارات | إنشاء قرار `decisions` وسجل `decision.created` | يرفض إنشاء القرار قبل أي كتابة عند غياب الدور التنفيذي. |
| `PMO` | `pmo.write` | المحافظ والمخاطر | إنشاء خطر `risks` وسجل `pmo.risk_created` | يرفض إنشاء الخطر قبل أي كتابة عند غياب دور PMO. |
| `PROJECT` | `project.read` و`project.write` | WBS والمستندات | إنشاء WBS وسجل `project.wbs_created`، وإنشاء مستند وإصدار أول وسجل `documents.document_created` | يرفض القراءة والكتابة عند غياب صلاحيات PROJECT. |
| حساب منخفض الصلاحية | عضوية بلا أدوار فعالة | المساحات الثلاث | لا يملك أثر أعمال | يثبت الرفض الموضع لكل عملية مسموحة فقط للأدوار أعلاه. |

## طريقة التشغيل والدليل

يشغل الأمر التالي تهيئة اختبار مستقلة ثم ملفات التكامل بالتسلسل. الترتيب متعمد لأن `pilot.roleAcceptance.database.test.ts` يقرأ كتالوج الصلاحيات المنشأ في `integration.database.test.ts` بدل إنشاء رموز متعارضة.

```bash
cd /home/ubuntu/project-os
node scripts/run-integration-database-test.mjs
```

في آخر تشغيل موثق لهذه الدفعة، مرّ المشغل بـ **60 حالة**: 59 حالة تكامل عامة وحالة قبول أدوار منظمة. تزيل التهيئة العقود والالتزامات التابعة قبل المشاريع، ولذلك يمكن إعادة تشغيل الدليل حتى بعد انقطاع سابق من دون ترك سجل يمنع تهيئة الاختبار.

## حدود معلنة وخطوة التسليم

لا يمكن لهذا الدليل تقليد تجربة جلسات OAuth البشرية على متصفحات وأجهزة وقراء شاشة مختلفة، ولا يدّعي ذلك. تبقى جلسة قبول يدوية واحدة مطلوبة قبل توصية `GO`: دخول مستخدم Pilot الحقيقي بأدوار EXECUTIVE وPMO وPROJECT وحساب منخفض الصلاحية، ثم تنفيذ نفس جدول السماح والرفض والتدقيق من واجهة الإنتاج. تسجل النتيجة مع هوية المسؤول ووقت التنفيذ ولا تستبدل بسجل الاختبار الآلي.
