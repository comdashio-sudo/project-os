# خطة ترحيل 0011 — الإشعارات الداخلية

## الهدف والنطاق

تنشئ الترحيل سجل إشعارات داخليًا داخل PROJECT OS فقط. لا ترسل بريدًا إلكترونيًا أو رسائل خارجية ولا تعتمد على تنفيذ مجدول. كل إشعار يخص مستأجرًا ومستلمًا محددين، ويمكن ربطه اختياريًا بمشروع وسجل أعمال، ثم يقره المستلم نفسه.

| قيد | تطبيقه |
|---|---|
| عزل المستلم | `recipientUserId` مفتاح أجنبي إلزامي؛ قراءة الإشعارات تقيد بالمستخدم الحالي والمستأجر. |
| عزل المستأجر والمشروع | `tenantId` إلزامي و`projectId` اختياري، مع فهرس للمستلم وحالة الإقرار. |
| النص الآمن | تخزن الخدمة رمز نوع وبيانات مرجعية فقط؛ تولد الواجهة النص العربي أو الإنجليزي، ولا تعرض حمولة خادم خام. |
| الإقرار | لا يستطيع مستخدم الإقرار بإشعار مستلم آخر؛ يكتب الإقرار وسجل التدقيق داخل معاملة واحدة. |

## الأثر والتحقق والاسترجاع

ينشئ `pnpm drizzle-kit generate` جدول `internal_notifications` وفهرس نطاق المستلم. بعد مراجعة SQL، يطبق الترحيل ثم يتحقق وجود الجدول والفهرس من `information_schema.tables` و`SHOW INDEX FROM internal_notifications`.

قبل وجود بيانات، يكون الاسترجاع حذف فهرس الجدول ثم الجدول. بعد استخدام السجل تشغيليًا، لا يحذف؛ بل تنفذ ترحيلات علاجية تحفظ السجل التدقيقي وتوثق الأثر.
