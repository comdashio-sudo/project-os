# دليل الدفعة 2.10 — استلام المواد والالتزام والتكلفة الفعلية

**الحالة:** `PROVEN` محليًا قبل الالتزام والدفع إلى `github/main`.

تربط الدفعة تسجيل GRN للكمية المقبولة بأثر اقتصادي واحد داخل المعاملة نفسها: **تكلفة فعلية منشورة**، وتخفيض مشتق لقيمة الالتزام المفتوح المتصل بأمر الشراء. لا تخزن الدفعة رصيد التزام قابلًا للتحرير، ولا تنشئ حركة مخزون من GRN، ولا تغيّر قيمة أمر الشراء أو الالتزام الأصليين.

| المتطلب | التنفيذ المثبت |
|---|---|
| مدخل التكلفة | يطلب عقد GRN وواجهة الاستلام `unitCost` موجبًا منتهيًا. يظل التحقق الخادمي نافذًا حتى عند تجاوز واجهة المستخدم. |
| مصدر التكلفة | تحسب المعاملة `actualCost = receivedQuantity × unitCost` للكمية **المقبولة** فقط، وتكتب `cost_entries` بحالة `actual/posted` وتاريخ الاستلام. لا تتحول الكمية المرفوضة إلى تكلفة. |
| ربط قابل للتتبع | يحمل GRN `costEntryId` فريدًا و`unitCost`؛ فلا يمكن وصل تكلفة فعلية واحدة بأكثر من GRN. يظل الربط قابلاً للقراءة والمراجعة. |
| تعريف الالتزام المفتوح | تقفل المعاملة أمر الشراء ثم الالتزام المرتبط به، وتجمع قيم GRN السابقة من الأمر نفسه. الالتزام المفتوح = `commitment.amount − Σ(receivedQuantity × unitCost)`. لا يُعدّل `commitments.amount`، فيبقى الأصل التجاري محفوظًا. |
| منع التجاوز | ترفض المعاملة أمر شراء بلا التزام، أو التزامًا غير `committed`، أو عملة مختلفة، أو تكلفة جديدة تتجاوز الالتزام المفتوح، قبل إدراج تكلفة أو GRN أو تدقيق. |
| الذرية والتدقيق | تكتب التكلفة ثم GRN ثم سجل `procurement.goods_receipt_note_created` في المعاملة نفسها، ويتضمن التدقيق التكلفة ومعرفها والالتزام والرصيد المفتوح قبل/بعد. فشل أي خطوة يعيد كامل الذرة. |
| الحراسة | تبقى عضوية المستأجر واستحقاق `PROJECT` وصلاحية `project.write` ونطاق المشروع، والتحقق من PO/المادة/فحص الجودة/NCR، شروطًا قبل المعاملة. |
| الواجهة | أضيف «تكلفة الوحدة / Unit cost» إلى نموذج GRN القائم بالعربية والإنجليزية. لا توجد شاشة مالية أو تدفق موازٍ، وتبقى رسالة الخطأ مارة بخريطة الأخطاء الموطنّة. |
| الترحيل | `0048_ambiguous_bishop.sql` يضيف `unitCost` الافتراضي الصفري للبيانات التاريخية و`costEntryId` الفريد ومفتاحه الأجنبي. روجع كإضافة غير هدامة وطُبق على MySQL/TiDB؛ أعاد Drizzle التوليد بلا فرق لاحق. |

## الدليل الحي

| الحالة | الدليل |
|---|---|
| رفض أمر شراء عابر | بقي `PROJECT_OS_PURCHASE_ORDER_NOT_FOUND` قبل أي كتابة. |
| رفض غياب الاستحقاق | عُطل `PROJECT` مؤقتًا ورُفض إنشاء GRN قبل أي أثر اقتصادي، ثم أعيد لمسار السماح. |
| السماح والرقم | أنشأ GRN بكمية مقبولة `8` وتكلفة وحدة `100` تكلفة فعلية منشورة `800.00`. |
| الالتزام المفتوح | كان الالتزام `1000.00`، ثم أعاد الاستعلام المشتق `200.00000` بعد الاستلام؛ لم تتغير قيمة الالتزام الأصلية. |
| الحراسة الاقتصادية | ظل عدد حركات المخزون صفرًا في سيناريو GRN، فلا تتداخل الدفعة مع حركة المستودع أو صرف المادة. |
| التدقيق والتنظيف | ثبت سجل تدقيق واحد وربط تكلفة واحد، ويزيل السيناريو التدقيق ثم GRN ثم التكلفة ثم أمر الشراء والالتزام قبل اختبار التدفق النقدي الشقيق. |

## حدود متعمدة

الكمية المرفوضة لا تخلق تكلفة فعلية في هذه الدفعة. لا ينشأ مخزون من GRN هنا لأن مصدر المخزون يبقى حركات المستودع المحكومة. كما لا يُعدّل الالتزام الأصلي؛ «المفتوح» قراءة مشتقة من GRN المقبول المرتبط بأمر الشراء. تبقى بوابة النشر `BLOCKED_BY_PLATFORM` والقبول البشري وبيانات Pilot الحقيقية خارج هذا الدليل.
