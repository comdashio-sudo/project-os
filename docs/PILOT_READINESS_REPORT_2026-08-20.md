# تقرير جاهزية Pilot المحكوم — PROJECT OS

**التاريخ:** 20 أغسطس 2026  
**حالة التوصية:** **NO-GO مشروط** لبدء Pilot ببيانات عميل حقيقية، إلى حين إغلاق قبوليْن يدويين محددين أدناه.  
**النطاق:** PROJECT OS فقط؛ لا يشمل TASLEEM أو أي قاعدة بيانات أو مستودع أو مورد تابع لها.

> يثبت هذا التقرير ما نُفذ واختُبر. ولا يحوّل نجاح البناء أو الاختبار الآلي إلى ادعاء قبول يدوي أو ضمان مزود خارجي لم ينفذ بعد.

## روجع هندسيًا

تستمر قاعدة البيانات الفعلية على **MySQL/TiDB Serverless** عبر `drizzle-orm/mysql2`. تنفيذ حماية سجل التدقيق مبني على حساب تطبيق مقيّد بـ`SELECT` و`INSERT` للسجل، مع حساب تدقيق إداري منفصل؛ وهو **ضابط صلاحيات حساب** وليس حصانة triggers، لأن المسار الحالي لا يستخدم triggers. وثيقة القرار والمشغل العملي موجودان في [ADR-0001](./ADR-0001-AUDIT-LOG-ACCESS-CONTROL.md).

لا يقبل الاستيراد ملفًا عامًا؛ إذ يطلب قالبًا واحدًا لكل نوع بيانات. قالب العقود يقبل رمز العقد والعنوان والطرف المتعاقد والقيمة والعملة فقط، ويمنع ملفًا متعدد الأوراق أو عمودًا إضافيًا أو عملة غير صالحة أو رمزًا متكررًا. توثق خطواته في [دليل الاستيراد](./IMPORT_EXPORT.md).

سياسة البيانات تميز بوضوح بين اختبار استعادة علاقة بيانات المستأجر في قاعدة اختبار معزولة وبين نسخ مزود قاعدة البيانات أو محتوى التخزين الكائني. يرجع تنفيذ اختبار الاسترجاع وخطوات إدخال بيانات العميل إلى [سياسة بيانات Pilot](./PILOT_DATA_POLICY.md).

## لم يراجع يدويًا ولا يجوز ادعاء إغلاقه

| بند | سبب عدم الإغلاق | الإجراء المطلوب قبل GO |
|---|---|---|
| قبول واجهة الإنتاج بهويات بشرية منفصلة | الاختبارات تضبط الهويات والـRBAC خادميًا، لكنها لا تمثل جلسات OAuth حقيقية على أجهزة المستخدمين. | تشغيل سيناريو [قبول الأدوار](./PILOT_ROLE_ACCEPTANCE.md) بحسابات EXECUTIVE وPMO وPROJECT وحساب منخفض الصلاحية وتسجيل النتيجة. |
| مراجعة قارئ الشاشة والأجهزة المختلفة | لا يمكن اختبار قارئ الشاشة الفعلي أو تفضيلات الوصول البشرية باختبار DOM أو لقطة غير موثقة الجلسة. | مراجعة يدوية على سطح مكتب وجوال وقارئ شاشة، مع قائمة مشاكل وتصنيفها أو إغلاقها. |
| استرجاع نسخة مزود TiDB ومحتوى التخزين | الاختبار المنفذ منطقي ومحدد النطاق داخل قاعدة الاختبار؛ لا يمثل استرجاعًا من واجهة مزود القاعدة أو تخزين الكائنات. | توثيق مسؤول النسخة الخارجي، وإجراء استعادة مراقبة للّقطة ومفاتيح الملفات على بيئة معزولة. |
| بيانات Pilot الفعلية | لا توجد هوية عميل قانونية أو مالك بيانات حقيقي لافتراضها. | اعتماد الاسم القانوني ومالك البيانات ونطاق أول مشروع قبل إنشاء المستأجر التشغيلي وإدخال أي بيانات. |
| فحص الإنتاج عبر متصفح Sandbox | ظهرت الصفحة الرئيسية بعد اكتمال hydration، مع الشعار والنص وزر اللغة وواجهة تسجيل الدخول؛ كانت اللقطة الأولى مبكرة قبل اكتمال التنفيذ. لا توجد جلسة OAuth مصرح بها في هذا المتصفح لاختبار المسارات المحمية. | تنفيذ سجل قبول الأدوار بجلسة Pilot حقيقية، ثم حفظ أدلة السماح والرفض والتدقيق. |

## الفروق عن آخر سجل Pilot

ارتفع دليل الوحدة والواجهة من 252 إلى **262** اختبارًا. ارتفع مشغل التكامل من 58 إلى **61** حالة، بإضافة قبول الأدوار المنظم ونسخ/استرجاع Pilot وقالب العقود ومركز الاستثناءات ضمن التغطية. بقي جرد tRPC عند **102** إجراء مع صفر إجراء غير مصنف. لا يعد هذا التقرير أن جميع مخاطر التشغيل أو الوصول اليدوي أغلقت.

## قرار GO / NO-GO

**القرار الحالي: NO-GO مشروط.** جاهزية الكود والحراسة والاختبارات مناسبة للانتقال إلى جلسة قبول Pilot محكومة، لكن لا يُسمح بإدخال بيانات عميل أو فتح Pilot تشغيلي حتى تسجل أدلة القبول اليدوي للأدوار والوصول، وتُحدد هوية المستأجر ومالك البيانات، ويؤكد مسؤول النسخ الخارجي اختبار الاسترجاع مع التخزين الكائني.

عند اكتمال البنود الأربعة السابقة دون نتائج حرجة، تعاد البوابة نفسها ثم يحدث هذا التقرير إلى توصية `GO` محددة النطاق.
