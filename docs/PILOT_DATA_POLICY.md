# سياسة بيانات Pilot والنسخ والاسترجاع

## الحالة المعتمدة

تحدد هذه السياسة الحد الأدنى لبدء Pilot محدود. أنشئ مستأجر Pilot **معزول في قاعدة الاختبار** باسم `PROJECT OS Pilot Restore Tenant`، وله مالك بيانات مسمى `Pilot Data Owner`، ودور شركة `PILOT_OWNER`، ومشروع بنية تحتية وعقد وسجل تدقيق. هذه بيانات اختبار معزولة فقط، ولا تمثل عميلًا أو بيانات تشغيل حقيقية.

| الأصل | المالك التشغيلي | مصدر الحقيقة | قاعدة الحماية |
|---|---|---|---|
| سجل المستأجر والعضويات والأدوار | مالك بيانات Pilot | MySQL/TiDB | لا تعديل مباشر خارج مسارات الإدارة المحكومة، ويؤخذ ضمن حزمة الاسترجاع بالترتيب العلاقي. |
| المشاريع والسجلات التجارية | مدير مشروع Pilot المفوض | MySQL/TiDB | الاستيراد يتم بالقوالب المعتمدة فقط، مع عزل المستأجر والمشروع وسجل تدقيق. |
| محتوى الملفات والمرفقات | مالك بيانات Pilot | التخزين الكائني | لا تحفظ البايتات في قاعدة البيانات؛ يجب جرد المفاتيح الوصفية ومراجعة قابلية استرجاع الأصل من التخزين. |
| سجل التدقيق | مسؤول التدقيق المعين | MySQL/TiDB | يحتفظ به ضمن نطاق المستأجر، ويكتب التطبيق بالحساب المقيد المخصص له وفق ADR-0001. |

## دليل الاسترجاع المنفذ

ينفذ الاختبار `server/pilot.backupRestore.database.test.ts` نسخة منطقية محددة النطاق إلى ملف JSON مؤقت خارج المستودع، ثم يحاكي فقدان المستأجر بحذف سجل الشركة ومالك البيانات والدور والعضوية وربط الدور والمشروع والعقد وسجل التدقيق. بعد ذلك يسترجع الحزمة بترتيب العلاقات الصحيح ويثبت بالاستعلام وجود العناصر السبعة بعد الاستعادة.

يشغل الدليل داخل قاعدة `project_os_integration_test` فقط عبر الأمر التالي؛ ولا يوجه أي كتابة إلى بيانات التشغيل:

```bash
cd /home/ubuntu/project-os
node scripts/run-integration-database-test.mjs
```

نتيجة أحدث تنفيذ للدليل هي **61 حالة ناجحة**: 59 تكاملًا تشغيليًا، وقبول أدوار منظم واحد، واختبار نسخ واسترجاع Pilot واحد. ينظف الاختبار المستأجر واللقطة المؤقتة بعد كل تشغيل، لذلك لا يمثل احتفاظًا أو نسخًا احتياطيًا فعليًا لبيئة الإنتاج.

> لا يكفي نجاح هذا الاختبار لادعاء أن نسخة مزود قاعدة البيانات أو التخزين الكائني قد استعيدت. إنه دليل قابل لإعادة التشغيل على ترتيب استرجاع بيانات المستأجر العلاقية داخل البيئة المعزولة فقط.

## إجراء Pilot قبل بيانات حقيقية

| الخطوة | المنفذ | الدليل المطلوب قبل الانتقال |
|---|---|---|
| تحديد الاسم القانوني للمستأجر ومالك البيانات الحقيقي ونطاق أول مشروع | مالك Pilot | سجل تشغيل يحدد المالك وبيانات التواصل ونطاق البيانات الأول. |
| إنشاء المستأجر والعضويات والأدوار عبر واجهة الإدارة المحكومة | مسؤول المنصة المفوض | معرفات المستأجر والأدوار وعضويات مالك البيانات وسجل التدقيق. |
| تصدير قالب العقود أو WBS المعتمد، وتنفيذ تحليل بلا تأكيد | مهندس التخطيط | ملف قالب مراجع، نتيجة تحليل خالية من الغموض، وتأكيد صاحب البيانات. |
| أخذ لقطة منطقية محددة النطاق وجرد مفاتيح الملفات قبل الإدخال الأول | مسؤول البيانات | معرف اللقطة، عدادات الجداول، قائمة مفاتيح الملفات، ومسؤول تنفيذ الاسترجاع. |
| اختبار استرجاع في قاعدة معزولة على نسخة من اللقطة | مسؤول البيانات | نتيجة تشغيل قابلة لإعادة التشغيل، فروقات العدادات، وموافقة مالك البيانات على النتيجة. |
| إدخال بيانات Pilot الفعلية بقوالب معتمدة | فريق Pilot | سجل استيراد مكتمل، نتائج الصفوف، وسجل تدقيق. |

لا تبدأ بيانات عميل حقيقية قبل استكمال اسم المستأجر ومالك البيانات الحقيقيين واعتماد مسؤول تنفيذ الاسترجاع. هذا تسليم تشغيلي لا يجوز استبداله باسم افتراضي أو ببيانات الاختبار المعزولة.
