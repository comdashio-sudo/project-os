# دليل الدفعة 6.د — إسناد العاملين والحضور وساعات العمل

**الحالة:** `PROVEN` قبل الالتزام. اجتازت البوابة الكاملة في 22 أغسطس 2026 على MySQL/TiDB. لا يغيّر هذا الدليل حدود Pilot المسجلة في `STATE.md`، ولا يرفع قيد النشر `BLOCKED_BY_PLATFORM`.

| شرط أمر العمل | التنفيذ والدليل القابل لإعادة التشغيل |
|---|---|
| نموذج الإسناد المتصل | يربط `employee_assignments` الموظف النشط بمورد **labor** وWBS ونشاط من المشروع نفسه. يرفض الخادم المورد غير العمالي، الموظف غير النشط، WBS/النشاط العابر، وعدم توافق النشاط مع WBS. لا يوجد نظام مهام موازٍ. |
| الساعات المخططة والطاقة | يحسب `assessEmployeeCapacity` السعة على أساس الأحد–الخميس، 8 ساعات يوميًا. يكتب الإسناد حتى عند التجاوز، لكنه يعيد الرمز `PROJECT_OS_EMPLOYEE_CAPACITY_EXCEEDED` وتحذيرًا ظاهرًا موطنًا؛ لا يوجد رفض صامت أو تغيير مخفي. |
| حضور محكوم بالمشروع | يقتصر سجل الحضور على العاملين ذوي الإسناد المخطط أو النشط في المشروع عند استخدام نطاق مشروع. حالاته `draft → submitted → approved/rejected`؛ وينفذ الانتقال بفعل واجهة صريح مع تدقيق ذري. |
| ساعات فعلية وتكلفة/تقدم | لا ينشئ الخادم مدخلة ساعات ما لم يوجد حضور **present** معتمد للموظف والتاريخ نفسيهما. تمر مدخلة الساعات بـ`draft → submitted → approved/rejected`. عند الاعتماد فقط تنشأ `cost_entries` فعلية منشورة، و`progress_entries` مرسلة عند إدخال نسبة تقدم. قرار الدفعة: `project_resources.unitCost` للمورد العمالي هو **تكلفة الساعة**؛ لذلك أثبت الدليل 8 ساعات × 150 = `1,200.00`. |
| RBAC الضيق | تستخدم الإسنادات وخياراتها وساعات العمل صلاحية `project.manage` في نطاق المشروع، لا `project.write` العام. يستخدم الحضور `project.attendance.manage` في نطاق المشروع. كتالوج `PROJECT_MANAGER` يملك الصلاحيتين، فيستطيع ضبط فريق مشروعه؛ لا يمنح ذلك قراءة بيانات راتب أو هوية PDPL المحمية. |
| واجهة التشغيل | يدمج `ProjectWorkforce` داخل مركز قيادة المشروع، ويعرض إدخال الإسناد والحضور والساعات، وسجلي حضور وساعات بحالات عربية/إنجليزية. لا ترسل الواجهة المسودات تلقائيًا للمراجعة أو الاعتماد؛ تظهر أزرار الإرسال والاعتماد والرفض وفق الحالة. لا تعرض بيانات راتب. |
| العزل والاستحقاق والتدقيق | يعطّل المشغل الحي استحقاق `PROJECT` صراحةً ثم يثبت رفض `assignments.create` و`attendance.create/transition` و`timeEntries.create/transition` قبل أي كتابة، ويثبت كذلك رفض المشروع والمستأجر العابرين. يعيد الاستحقاق بعدها فيثبت السماح داخل النطاق وسجلات تدقيق للإسناد والحضور والساعات، ورفض الساعات قبل حضور حاضر معتمد، ثم اعتماد الحضور والساعات والتكلفة والتقدم. |
| تنظيف الدليل الحي | يحذف التنظيف النهائي بالترتيب: `employee_time_entries` ثم `employee_attendance` ثم `employee_assignments` قبل التقدم/التكلفة والأنشطة والموارد والموظفين، كي تبقى إعادة تشغيل الدليل آمنة مع قيود المفاتيح الخارجية. |
